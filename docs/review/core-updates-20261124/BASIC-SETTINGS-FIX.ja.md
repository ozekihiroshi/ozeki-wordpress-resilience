# 基本設定9項目の日常保存修正（2026-11-24）

## 修正

初回保存だけに含まれていた次の設定を、UpdateContractの共通対象に移した。

- キャッチフレーズ（blogdescription）
- カテゴリー・タグURL（category_base、tag_base）
- 日付・時刻表示（date_format、time_format）
- 週の開始曜日（start_of_week）
- RSS件数（posts_per_rss）
- 新規記事のコメント・ピンバック受付の既定値（default_comment_status、default_ping_status）

SiteSnapshotはこの共通対象を初回保存に使い、CoreStateHistoryは同じ対象から変更検知・記録・適用を行う。設定の削除通知も既存の変更検知を使用するが、今回は通常の設定値変更を実測した。設定一式の対象と既定値のキー一致も検査する。

テーマ選択やプラグイン構成を日常保存の対象へ混ぜない。未確認のサイトアイコン・ページ参照・テーマ関連の変更は今回の修正に含めない。残る初回保存対象の方針がすべて確定したという意味ではない。

## 記録形式

更新契約・原本・初回保存・独立索引を `core-updates-4` 系へ更新した。旧版が設定の一部を読み飛ばしたり、同じ識別子の異なる項目一覧を解釈したりすることを防ぐ。

公開前候補間の保存データ互換性は保証しないという既存方針を継続する。保存元と復旧先を同じ対応版に揃え、健全な保存元で新しい初回保存を作る。既存の原本・履歴は書き換えない。core-updates-3の実読取り処理で、新原本・初回保存・独立索引がすべて拒否されることを確認した。

## 確認結果

修正前に `tests/basic-settings.php` が `Daily contract must cover blogdescription` で失敗し、修正後は成功した。9項目の値と型の維持、復旧先のプラグイン構成・テーマ選択が変更されないことを照合した。既存のメニュー・分類・記事の契約テスト、安全な適用規則と原本形式のテストも成功。PHP構文とdiffチェックも成功。

dmの使い捨てDocker環境で次を確認した。

| 操作 | 結果 |
| --- | --- |
| 9項目を変更して復旧 | 全項目一致。変更単独で正式履歴を記録 |
| 続けて記事本文を保存し復旧 | 設定と本文が一致 |
| 新しい初回保存から復旧 | 一致 |
| 復旧先で9項目を再変更・再保存し再復旧 | 全項目一致 |

キャッチフレーズ、日付・時刻、カテゴリー・タグURLはWordPress標準取得関数の出力も一致した。他の項目は設定値の照合であり、RSSのHTTP配信、カレンダー描画、新規投稿でのコメント受付を実測したという意味ではない。

ファイル保存へ差し替えたS3 SDKを使用し、実S3や本番には接続していない。試験開始時の保存オブジェクトはハッシュ一致。試験コンテナは削除した。要約は `basic-settings-verification.json`、詳細は非公開試験領域 `release-readiness/basic-settings-fix-20261124` のresult.jsonとrun.log。

本番・既存原本・履歴・ZIP・タグは変更していない。rc.21 ZIPのSHA256も従来と一致。mainへの取り込み、push、Actions実行、Plugin Check、新ZIP、申請・メール返信は行っていない。
