# 日常更新の保存・復旧修正：確認結果

2026-11-24。分離した作業ブランチでの確認。main・本番反映・公開は未実施。

## 修正した内容

初回保存だけにあった情報を、日常履歴の保存・適用にも揃えた。
記事の値と投稿者の定義を共有する契約を追加し、分類・基本設定・
記事のごみ箱操作については操作完了後の状態を既存の正式履歴キューへつないだ。

| 対象 | 隔離WordPressでの結果 |
|---|---|
| 記事のパスワード | 設定・解除、非公開・ごみ箱状態を復旧。パスワードを残した再保存・再復旧でも、匿名閲覧時のパスワード要求が維持された。 |
| 投稿者 | 変更した投稿者の表示名・名前を復旧。本文・抜粋・親ページ・表示順・コメント受付設定も一致。再保存・再復旧でも一致。 |
| カテゴリ・タグ | 名称・slug・説明、祖先の名称・親、タグ・カテゴリの削除を反映。削除済み定義を残さず、割当も一致。再保存・再復旧も一致。 |
| 記事に伴うコメント状態 | ごみ箱移動・解除・記事削除を反映。復旧先で実際にごみ箱を解除しても、承認状態と元のURL名へ戻った。 |
| 基本設定 | トップページ、サイト名、タイムゾーン、一覧件数の変更を反映。再保存・再復旧も一致。 |

復旧後のごみ箱解除では追加の不足を発見した。コメントは戻ったが、記事のURL名に
`__trashed` が残った。WordPressが使う `_wp_desired_post_slug` を保存・適用の対象に加え、
解除操作から再保存・再復旧まで再確認した。独自の初期化・代替処理は追加していない。

## 再発を検出する確認

- 必須項目の欠落とパスワードの明示的な解除を区別する。
- 投稿者の構造化情報を配列のまま比較し、変更を保存済みと誤認しない。
- 記事詳細の古い分類の写しから、削除した分類が復活しない。
- 別の分類と共有された用語を、カテゴリ削除に巻き込まない。
- 許可していないソフトウェア設定を、基本設定履歴から適用しない。
- S3の履歴確定を失敗させると未完了として残り、凍結済み原本を変えずに再開できる。
- 復旧後にWordPressで操作・再保存し、別の新規WordPressへの再復旧を比較する。

関連する既存のキュー検証、適用規則、編集保存・nonce、添付契約、指定時点復旧、
非インストール方針の確認も実施。契約・適用規則の主要確認はPHP 8.1と8.3で通過した。
追加したオフライン確認はActionsの既存ワークフローへ接続したが、GitHubへのpushと
Actionsの実行はこの段階では行っていない。

## 互換性と保全

旧原本の読み取りを維持し、変更していないrc.21が新しい原本・全体保存・索引を拒否することを確認した。
移行は保存元と復旧先を新版に揃え、健全な保存元で新しい初回保存を作る方式とする。
パスワード変更が欠ける旧記事履歴は、自動公開できる復旧点として扱わず、書換え前に案内する。

本番、既存S3の原本・履歴、提出済みrc.21のZIP・タグ、研究側の未コミット変更は変更していない。
隔離試験でも、再保存前から存在したオブジェクトのハッシュ不変を確認した。

## 確認範囲と次の段階

今回の往復確認は、dmの専用Docker・合成データ・外部通信を止めたWordPress 7.1.4/PHP 8.3と、
ファイルを使う模擬S3で実施した。初回復旧先と再復旧先はそれぞれ新規に準備した。
ブラウザでの画面操作と実S3での統合確認は今回の結果に含めない。
