## 基本構成と対象

正常な登録手順でS3へ先に保存したものを正常な原本とする前提を採用します。既存WordPressとS3で動かし、常設の別EC2は要求しません。復旧時に新しいWordPressを用意します。

初期対象は会社案内・サービス・連絡先の3ページとJPEG/PNG。本文は段落・見出し・リスト・リンク・画像位置、関係はページの親子・メニュー順・リンク先を扱います。連絡先は住所・電話・メールへのリンクで、問い合わせフォームの実行は含めません。独自PHP、ショートコード、動的ブロック、任意HTML/スクリプト、PDF/SVG、独自プラグインの状態は対象外です。未対応内容は保存前に知らせ、無言で捨てません。必要なら利用者が対応形式への変更を選びます。

Markdownでの執筆は要求しません。最初の保護対象入口はResilienceの明示的な保存・公開操作です。通常エディター全経路への統合ができるまでは、通常保存・REST・CLI・インポートをすべて保護できるとは表示しません。ローカル下書きは「S3未保存」として許容します。

## 原本の単位

| 単位 | 保存内容と更新方法 |
|---|---|
| サイト | ドメインや旧WPのIDに依存しないsite_id |
| ページ原本 | 1ページの1回の確定変更。独立asset_idとrevision_id、タイトル、希望slug、対応範囲の本文構造、言語、操作ID、由来 |
| 画像原本 | アップロードされたJPEG/PNGのそのままのバイト列。画像の差替えは新しい版。サムネイルは再生成可能な派生物 |
| 関係情報 | 小規模なのでサイト全体を1版として保存。親子、メニュー順、本文内のリンク位置・アンカー、画像位置・代替文・説明と、参照する厳密な資産版 |
| 再構築設定（Profile） | 3つの役割に対応するページ、必須画像、言語、対応するクリーンテーマと変換規則、了承済み代替表示。秘密情報や旧options一式は入れない |
| サイト世代 | 3ページ・画像・関係・Profileの固定版を束ねる目録。親世代、操作ID、ハッシュ、サイズ、S3のkeyとVersion IDを記録 |
| WP反映記録 | その世代を元サイトへ反映できたかを別記録にする。原本目録を後から書き換えない |

IDは時刻や旧WPの数字IDではなく独立した識別子にします。同じ画像を2箇所で使うなら原本は1つ、使用関係は2つです。代替文だけの変更で画像を複製しません。本文はWPへの正式反映前に対応する構造で保存します。編集元形式も残す場合は証拠用と区別し、再構築は対応範囲の構造を入力にします。

内部リンクは元ドメインのURLだけでなく対象資産とアンカーを記録し、新サイトのURLに組み直します。解決できない内部リンクは利用者が修正・削除・代替するまで完成扱いにしません。

## サイト世代の確定

世代はサイト全体の論理的なスナップショットです。変更したものだけ新しい原本を作り、変更のないものは固定版を再参照します。必須3ページは常にそろえ、役割を引き継ぐページなしに削除できません。任意画像の削除は新世代からの除外で、過去原本の削除ではありません。

1. 操作ID・変更内容のハッシュ・想定する親世代を固定する。その後の編集は別操作にする。
2. 内容と必須項目を検査し、原本・関係・ProfileをS3へ保存して固定版を確認する。
3. 同時編集を直列化し、親世代が進んでいたら競合として止める。勝手な後勝ち上書きはしない。
4. 全参照先と保持条件がそろった時点で、変更できない完成世代の目録を保存する。
5. その世代をWordPressへ反映し、結果を別に記録する。

S3とWPを一つのトランザクションとして扱いません。**利用者への通常の保存完了は「S3確定＋WP反映完了」**です。公開するかどうかは別です。S3だけ成功なら「S3保存済み・WordPress反映待ち」と表示します。この世代は再構築可能ですが、以前公開されていた内容と同じとは扱いません。最終確定世代と最終反映確認世代を区別します。

最新ポインターだけを復旧の根拠にしません。並行PHP処理、停止した実行者からの引継ぎ、古い実行者の書込み拒否を扱う確定方式が必要です。具体的な条件付き更新方式は実装前の設計事項で、常設別サーバを前提にしません。

## 失敗と再開

状態は「準備→保存中→原本確認済み→世代確定→WP反映済み」。失敗時には最後に確認できた段階、エラー、競合、結果不明を残します。

| 状況 | 動作 |
|---|---|
| S3保存に失敗 | 前の完成世代を維持。保護対象の正式なWP変更は進めず、下書きを残す |
| 一部だけ保存 | 確認済み固定版を再利用し、照合後に不足だけ保存。未完成世代を復旧候補にしない |
| 応答がなく結果不明 | 同じ操作・原本IDで保存結果を確認してから再送。異なる内容ならエラー |
| 世代確定の結果不明 | 確定結果を照合するまでWP反映や次世代作成を止める |
| S3確定後にWP反映失敗 | その世代から反映を再開。WPを再抽出したり原本を登録し直したりしない |
| WP反映後に結果記録失敗 | WPとの対応と内容を確認して記録を補う。ページや画像を重複作成しない |
| ブラウザ・PHPの停止 | 保存済みの段階から再開。未送信の画像は必要なら再選択してもらう |
| 世代確定前に保存元喪失 | 保証するのは前の完成世代まで。一部原本は素材として扱い、完成したサイトとは呼ばない |

連打は同じ操作に結び付け、意図した内容変更は新操作にします。自動再試行は1回の処理につき最大3回を初期案とし、間隔を空けます。認証・内容・競合エラーは人の対応を待ちます。画面からの再開を基本とし、常時動作ワーカーは必須にしません。操作を取りやめてもS3素材を自動削除しません。S3に到達していない下書きまで保存元喪失から守れたとは扱いません。

## 保持期限

**最低保護期間・整理可能になる時点・実際の削除を分けます。** 初期案は新しい完成世代につき最低35日の保護で、35日後の自動削除ではありません。目録だけでなく、その世代が参照する全原本・関係・Profileの固定版を同じ期限以上まで保護できることを、確定条件にします。

古い画像を新しい世代で使う場合、次の順に扱います。

1. 通常の書込み権限には、対象を限定した保持延長だけを認める設計とする。短縮・保護回避・削除は認めない。
2. この境界を実際の権限で保証できない構成では、広い保持変更権限を与えず、同じ原本の新しい保護付きコピーを作るか、確定を失敗として止める。
3. コピーしても論理的な原本版・由来・ハッシュは維持し、格納先だけを区別する。署名承認期限の自動延長はしない。

**初期仕様では自動整理をOFF、原本・目録の年齢による自動失効を設定しません。** 半年間更新のない企業サイトでも、現在の復旧材料を保持するためだけの日次処理は不要です。最低保護期間を過ぎても通常サイトの権限では削除できない構成にします。ただし保存管理者に対する無期限の時間ロックを保証するものではありません。より長いロックは明示的な選択肢です。

将来の整理候補は、後継世代があり最低保護期間を過ぎた履歴に限ります。最新確定世代、最新反映確認世代、固定した初期基準、利用保留・復旧中の世代、未解決操作に必要な資産は除外します。削除する原本を参照する保持対象が一つでもあれば削除しません。参照や保留情報が不明・古い場合も整理を止めます。dry-runと直前の再確認を経て、別の整理権限で行う方針で、削除実装は初回範囲外です。

保管量は整理まで増えるため、容量と世代数を表示します。費用削減を理由に勝手に自動削除へ切り替えません。保持中であっても利用保留された版を復旧に使用してよいとは限りません。独立した最新の保留記録を確認する仕組みは、侵害対応製品として出す前に別途確定が必要です。

## 例と次の範囲

G1＝会社C1・サービスS1・連絡先T1・画像I1。サービスのみ編集するとG2＝C1・S2・T1・I1です。I1の保護期限がG2に足りなければ延長または保護付きコピーを先に行います。S2の保存だけで止まったらG1を維持。G2確定後にWPが止まったらG2の反映待ちとして再開します。G3で画像を外しても、G1/G2を残す間はI1を削除しません。

次に実装する単位は、この3ページと画像1枚の「S3先行保存→世代確定→WP反映→失敗時再開」です。実装前に確定する技術事項は、同時更新の確定方式、保持延長の限定権限、WordPressの保存入口の制御方法です。旧Restoreの承認条件・既存S3・Backup for S3は変更しません。今回の文書をもって実装済み・実証済みとはしません。
