# 次マイルストーンへの提言

M1は正常な模擬資産から復元する機能の実証である。次は、保存側が侵害されても復旧能力を失わない境界を実証する。フィールドを増やすことより、信頼の起点と証拠の運用を優先する。

1. **権限の分離**：dmに復旧専用ロールを割り当て、固定版GETの成功、PUT・削除の拒否、保存側から復旧ロールを取得できないことを検証する。既存dmの業務権限を先に棚卸しする。
2. **Root of Trust**：anchorの署名、検証鍵の独立配布、管理者交代、鍵紛失・失効・更新時の手順を確定する。同じAWSアカウントの管理権限が失われるケースも検討する。
3. **保持と破壊耐性**：Versioningだけに依存せず、別アカウント保管やObject Lockの保持方式・費用・誤設定からの回復を設計する。破壊試験は専用資産で行い、既存バケットへ無断で保持ロックを適用しない。
4. **汚染からの復旧**：固定版とハッシュの一致は安全な内容の証明ではない。汚染前のセット選定、コードの配布元検証、DB内の不正データ、秘密情報のローテーションと復元後の検査基準を作る。
5. **別ホストでの再現性**：Docker未導入の復旧ホストから開始し、別担当者が手順書だけで復元する。元のホストOS・SSH設定・作業者の知識への依存を測定する。
6. **整合点と証拠の期限**：更新中サイトのDB・メディアを整合して取得する。E1/E2/E3の観測時刻・適用範囲・期限・失効理由を定義し、過去のE3成功を現在の復旧可能性に読み替えない。
7. **運用製品化**：初心者向け事前診断、復旧ロール設定案内、容量・費用の予算、失敗時の安全な再開、定期復元演習を実装する。製品構成はADR 0004で更新し、両製品が単独導入できるよう共通バックアップ部品を同梱する方針とした。Resilienceは資産の組合せ、独立取得、復旧と証拠評価を担う。既存manifestの互換読込みは独立したアダプターとして契約試験を設ける。

次の完了条件は「復元できた」だけでなく「保存主体の資格情報で復旧用資産・信頼情報を破壊できない」「独立した担当者が信頼を確認して復元できる」とする。侵害試験の範囲・合格基準・費用は、実行前に具体化する。
