# Phase 1 復旧比較用の基準データ

更新日：2026年10月17日。基準定義。実測はevidence/m1/phase1/に保存する。

## サイトとデータ

すべて模擬データとし、WordPressの初期サンプルデータも存在し得るため、全体件数だけで判定せず識別子と内容で比較する。

| 対象 | 基準 |
| --- | --- |
| 固定ページ | 会社案内、サービス、お問い合わせ。各本文にOWR-HOME、OWR-SERVICES、OWR-CONTACT |
| 投稿 | 復旧検証のお知らせ。本文にOWR-NEWS |
| 文字列 | 日本語、絵文字🌱をDBとHTTP表示で扱う |
| 構造化option | owr_fixture_nestedのmessage、enabled=true、count=7 |
| フロントページ | 会社案内を固定ページのトップに設定 |
| 内部リンク | トップからサービス、お問い合わせへのリンク |
| 画像 | 自動生成PNG、64×48、owr-image.png |
| PDF | 自動生成1ページのowr-guide.pdf |
| 添付関係 | 画像・PDFの親が会社案内。相対パス、サイズ、SHA-256を保存 |
| テーマ | twentytwentyfive。実際の版を記録 |
| プラグイン | 固定したOzeki Database Backup for S3 0.3.0を有効化 |
| 管理者 | owradmin。ランダムな専用パスワードでHTTPログイン |
| 問い合わせ | shortcodeによるダミーフォーム。OWR-SYNTHETIC-INQUIRYにOWR_FORM_ACCEPTEDを返す |

## 検査方法

fixture/verify.phpは、DB内の投稿・設定・添付関係、ファイルのSHA-256、プラグイン有効化、テーマ、外部HTTPとメールの無効化を確認する。

tools/verify-m1-http.pyは、トップ、固定ページ、投稿、画像、PDF、内部リンク、実際のログインと管理者プロフィール、フォームの正常応答、不正nonceの403拒否をHTTPで確認する。

ソフトウェアの版、各資産IDとハッシュ、検査結果はsource-baseline.jsonに記録する。HTTP検査はhttp-checks.jsonに記録する。ハッシュ基準は初期生成時のDB内情報に基づくため、Phase 3で外部の固定Recovery Setに結びつけるまでは独立した信頼の起点とは扱わない。

## 復旧試験での利用

後続の試験では、復元したDB・ファイル・HTTP機能をこの基準と比較する。元サイトの動作検査に合格しただけで復旧成功とはしない。URLを変える場合は、シリアライズされた値やリンクへの影響を考慮して、比較ルールを試験前に定義する。

今回のフォームは配送サービスや業務システムとの連携を含まない。対象事業の問い合わせ再開を認定する場合は、その実機能を別途試験する。

## Phase 1での実測結果

DB・ファイル等16項目、HTTP14項目が合格した。画像・PDFの原本2件に加え、WordPressが生成した派生ファイルを含むuploads全5件のハッシュを記録した。復元後には原本だけでなくこの全体を照合する。環境分離18項目も別途合格した。
