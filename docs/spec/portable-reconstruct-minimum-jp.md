# 独立した情報素材と最小Reconstruct仕様

[English（主仕様）](portable-reconstruct-minimum.md) | 日本語

2026年10月22日。**調査・設計のみ。未実装・未検証で、本番利用の承認ではありません。** WordPress公式資料と既存ソースを静的に確認しました。実サイトへのアクセス、DB取得、エクスポート、クロール、復元、本番変更は行っていません。特定サイトで何割取り出せるか、変換精度は未測定です。

## 何を完成させるか

元のWordPress・管理元が失われても、会社案内・サービス・連絡先などを独立した素材から再建できることを目標にします。元のデザインやプログラムの完全再現ではありません。

最小構成は、単一サイト・単一言語の選択した公開済み標準投稿／固定ページと、使用するローカルJPEG/PNG画像です。最初の出力はネットワーク不要の静的プレビュー。元のPHP、JavaScript、フォーム、外部フォント、追跡コードを使いません。WordPressへの投入と本番公開の自動化は後段です。Backup for S3との連携・機能吸収もまだ行いません。

## 調査で分かったこと

WordPressのブロックはpost_contentへシリアライズされます。保存された本文は取り出す材料になりますが、それだけで独立した表示が再現できるとは限りません。[公式のデータ形式説明](https://developer.wordpress.org/block-editor/explanations/architecture/data-flow/)。

WXRにはコンテンツのレコードを出せますが、添付ファイル本体とサイト設定は含まれません。投稿タイプのエクスポート設定による制約もあります。[WP-CLI export](https://developer.wordpress.org/cli/commands/export/)、[export_wp](https://developer.wordpress.org/reference/functions/export_wp/)。WXRだけで自己完結した保管にはなりません。

ページとメディアの標準APIは、親、表示順、リンク、アイキャッチ、代替テキスト、メディア情報などを記述しています。これは関係抽出の材料であり、画像実体の取得や全参照の網羅を保証しません。[Pages](https://developer.wordpress.org/rest-api/reference/pages/)、[Media](https://developer.wordpress.org/rest-api/reference/media/)。動的ブロックは表示時に生成されるため、保存本文だけでは不足します。[Dynamic blocks](https://developer.wordpress.org/block-editor/how-to-guides/block-tutorial/creating-dynamic-blocks/)。以下の扱いはこれらに基づく本プロジェクトの設計判断です。

## 抽出できる範囲・欠落・依存

| 対象 | 独立保存する材料 | 最小版での再構築 | 欠落・依存として示すもの |
|---|---|---|---|
| 基本本文・静的ブロック | 元本文、タイトル、抜粋、日時、元ID/URL | 段落、見出し、箇条書き、強調、引用、文字・コード、許可リンク・画像 | CSS、装飾、未対応HTMLを除去した位置と理由 |
| 表 | 元HTML・属性 | 初版は原資料保管と要確認表示 | セル結合・レイアウト・意味を勝手に平文化しない |
| ページ・投稿 | 安定した素材ID、種別、公開状態、slug、日時 | 一定のパスを持つ独立ページ | テーマ、一覧画面、元URLの動作そのもの |
| 親子・順序 | 親ID、表示順 | 階層と確認済みナビゲーション | 親子関係とメニュー所属は別 |
| メニュー | 取得可能な項目・参照先・順序 | 既知のページへのリンク。取れなければ階層から案を作る | テーマの配置場所、条件付き・プラグインメニュー、不明な宛先 |
| 本文画像・アイキャッチ | 実ファイル、元URL/ID、alt、caption、ハッシュ | 検査・再エンコードしたJPEG/PNGをローカル参照 | トリミング、srcset、アニメーション、メタデータ、背景画像 |
| 内部リンク・アンカー | 元href、本文位置、対象ID/URL/fragment | 判別できる対象を素材内へ結び直す | 別名URL、クエリURL、不明なアンカーは未解決表示 |
| 分類・タグ | 名前・ID・所属 | メタデータ保持 | 分類一覧・検索機能は後段 |
| 同期・再利用ブロック | 参照先IDと内容 | 初版は依存を検出して要確認 | 循環、参照切れ、版の不一致、独自描画 |
| 動的ブロック・ショートコード | 保存属性・文字と依存先 | 未対応表示。人が確認した代替文を使用可能 | PHP・DB照会・プラグイン・外部サービスによる生成 |
| 独自フィールド・ビルダー・独自投稿 | 明示選択した取得可能な元データ | 依存一覧まで。専用変換は後段 | 独自スキーマ・専用テーブル・本文外の情報 |
| ヘッダー・フッター・ロゴ・連絡先 | 取得可能な選択設定・参照・元データ | 会社情報とナビゲーションを担当者が指定・確認 | 本文以外のテーマ、ウィジェット、ビルダー設定 |
| フォーム・地図・動画 | 表示名と参照先 | 動作を除去し、確認済みの説明・リンクへ | 送信・外部表示・API接続は復元しない |
| PDF・SVG等 | 原ファイルと種別・ハッシュ | 制限付き原資料保管。自動公開しない | 能動的機能・内容・解析の別方針が必要 |
| ユーザー・秘密・サイト設定全体 | 公開素材から除外 | アカウント・秘密・旧options・実行コードを投入しない | 新規設定・再接続は別作業 |

「原資料として残る」と「再構築できる」を別に数えます。必須の会社案内PDFが未対応なら合格にせず、別の扱いを決める必要があります。未知の要素を黙って捨てたり、実行して内容を調べたりしません。

## 取得・変換の方式

通常運用時、明示選択した公開ページと必要な情報・画像実体を収集する構造化エクスポートを第一案とします。ページングと全件数を照合します。下書き・非公開・パスワード保護・リビジョン・コメント・ユーザー・全カスタムフィールドは初期対象外です。公開ページの元データにも非公開情報が混ざり得るため、原資料はアクセス制限します。

変換側は保存したデータだけを解析します。旧PHP・テーマ・プラグインを読み込まず、ショートコードやrender callback、SQLを実行しません。WordPressで動くエクスポーター自体はインストール済みフック等の影響を受けるので、読取り意図だけで侵害耐性が得られるわけではありません。

RESTは補助経路として使えますが、描画済み本文と元本文は別で、権限・取得context・独自公開設定にも依存します。WXRは必要に応じた原資料であり、唯一の正本にはしません。任意URLの取得や公開サイトのクロールを網羅性の根拠にしません。外部URLの自動取得によるSSRFや認証情報持出しも防ぐ必要があります。

取得開始・終了、対象、更新マーカー、画像ハッシュを記録します。途中変更・不足・中断はpartial/unstableとし、正常な前世代を置き換えません。更新日時の一致だけで原子的な取得とは断定しません。既存の取得整合性契約は対応可能な構成で再利用候補ですが、今回の素材取得に自動的に適用済みとはしません。侵害後のオフラインSQL抽出は最小版の対象外です。

## 素材パッケージ案

現行Recovery Setとは別の新しいスキーマ案です。

| 場所 | 内容 |
|---|---|
| manifest.json | スキーマ・版、素材集合ID、取得期間、対象／必須ID、入口、件数、ハッシュ、整合性、変換方針、依存と欠落の集計 |
| raw/ | 選択した元レコードと任意のWXR。Web公開ディレクトリには絶対に含めない |
| content/<id>.json | 正規化した本文要素、タイトル、元ID/URL、日時、親子・順序、画像・リンク参照。機械処理の正本 |
| readable/<id>.md | HTML無効の限定Markdownによる閲覧用派生物。素材内の画像・ページを参照し、未対応箇所を明示 |
| media/originals/ | 制限付き原画像。元の名前・URLを索引へ保持し、安全なIDで格納 |
| media/derived/ | 大きさ・処理量を制限して検査・再エンコードしたJPEG/PNG。元との対応とハッシュ |
| relations.json | 親子、メニュー、本文リンク、画像、アイキャッチの関係と、未解決理由 |
| issues.json・説明書 | ページ内位置、保存／変換／除外／不明、重要度、代替案、担当者の判断。WordPressなしでの読み方 |

Markdownだけを正本にせず、元情報・構造・人が読む形式を分離します。Markdown編集からの再投入は初版対象外です。再エンコードも無害化の保証ではありません。

パス逸脱、symlink、ファイル名衝突、サイズ・展開量過大、XML外部実体、任意オブジェクト生成を拒否します。必要なツール・依存物とアクセス／信頼の初期条件は別途明示し、元ドメインや元DBを隠れた必須条件にしません。

## 静的再構築と担当者確認

清潔な固定テンプレートとCSSで、許可した型の本文だけから新しい出力先にHTMLを生成します。文字をescapeし、生HTML、イベント属性、危険なURL scheme、JavaScript、iframe、form、自動外部通信を持ち込みません。内部リンクは文字列置換でなく元origin/path/IDの対応で解決し、guidを公開URLと同一視しません。

未解決リンクと依存は表示します。外部ハイパーリンクは取得せず確認対象にし、メール・電話の宛先も確認後に採用します。別形式や任意ファイルを公開フォルダへそのままコピーしません。

取得完了、変換可能、プレビュー生成、担当者確認、公開承認は別の状態です。どれも無侵害の証明ではありません。必須情報の不足は公開準備完了を妨げますが、救出済みの資料を見ることまでは妨げません。要件削除・代替情報の採用は人が明示して記録します。

人が判断するのは、必須ページ、変換できない箇所、会社名・連絡先などの重要情報、最終公開です。正常な文字列でも攻撃者が書き換えた連絡先かもしれません。独立して承認した資料があれば照合し、なければ未確認として人が確認します。ハッシュや新しいテンプレートから情報の真実性は導けません。

## 既存機能と必要な新規実装

既存のfirst-site-capture.pyはDB／ファイルの整合性、アーカイブとハッシュを扱い、first-site-docker-lab.pyは添付ファイルの参照を列挙しています。S3固定版・保持・署名・失効の部品も再利用候補です。

一方、確認したtools/src範囲では、可搬本文への正規化、変換欠落の分類、可搬なページ関係グラフ、静的再構築器は見当たりません。既存の生成サイト復元試験は、これらの動作の証拠にはなりません。保管に接続するときも新しい資産形式への明示的な対応が必要で、旧署名を再構築結果の公開承認へ読み替えません。

実装順は以下に絞ります。

1. 対象・必須ページの選択と、読取り専用の抽出可否一覧。
2. 素材パッケージ、限定本文変換、全対象を説明できる欠落一覧。
3. 元システムなしで動く静的プレビューとリンク照合。
4. 重要情報の確認、再現可能な生成結果の記録。
5. 必要に応じ、既存の固定版保管へ接続。

WordPress再投入、多数のビルダー対応、自動公開、監視・systemd・VMの拡張を先行させません。

## 将来の合格条件（今回は試験しない）

標準本文に加えて、未対応ショートコード・表・ビルダー情報・切れたリンク・欠落画像を意図的に含む小さな企業案内の試験データを使う予定です。対象全件を保存／変換／要確認／阻害として説明できることを求めます。

元サイト・ドメイン・DBを使わず素材が読めて、プレビューが作れること。必須情報は存在するか、欠落として公開準備を止めること。非公開情報・秘密・旧実行コードを出力せず、外部通信せず、同一素材とツール版で同じ出力になること。必須の企業情報を人が確認できることが合格条件です。件数・時間・容量は将来実測し、根拠のない成功率や完全性保証にしません。

今回は環境・試験基盤の新たな実測結果はありません。上記の製品課題は未実装能力であり、未実行試験の失敗ではありません。過去の障害記録は別扱いです。実サイトの内容調査・抽出は、対象と保存先を別途合意してから行います。
