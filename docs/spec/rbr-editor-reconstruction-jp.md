# 編集世代から署名付き再構築へ（試作）

3ページ編集の実API応答を `rbr-generation-kit.py --generation SAVE_RESULT.json --profile PROFILE.json --work NEW_PRIVATE_DIR --execute-generated-lab` へ直接渡せます。固定世代参照を維持し、マニフェストの世代番号も照合します。応答は取得先の指定であり、署名承認の代替ではありません。編集資産を試験データ生成器で作り直しません。

Qは再構築より前に期待値として定義してS3固定版にします。今回の `examples/rbr-editor-expected.json` は3回の編集で期待する文章・画像・関係を明示しています。復元したDBや成功結果から正解を逆算しません。内容変更時のQと必須業務情報の更新・確認は担当者の作業で、汎用の自動Q作成や管理画面は未実装です。古いQは比較失敗とし、結果に合わせて書き換えません。

各世代は完全スナップショットです。parentは元の世代バイト列に残る来歴参照で、復旧時の必須入力にはしません。作成側・取得側・取得後の整合性検証で同じ規則を使い、既知の完全世代スキーマのparentだけを追跡対象から外します。当該世代、実際に使う本文・画像・関係・規則・環境・Qの固定版と保持条件は引き続き検査します。未知フィールドは拒否し、他スキーマのparentは通常どおり検査します。過去の系譜が検証済みという意味ではなく、旧版の保持延長・削除も行いません。

復旧キットは独立署名承認待ちで止まります。署名・最新失効台帳・有効期限・実行直前の再検査を維持し、既存承認を延長しません。試験用に明示承認したキットから非公開WordPressを2回作り、Qとの一致を検査します。ページは下書きのままとし、自動公開しません。

実S3試験ではブラウザ編集3世代と実際の適用済みAPI応答を使用します。元WordPressの専用コンテナを削除し、復旧時には取得元のローカル素材を別マウント名前空間で隠します。実行イメージの既存キャッシュは再利用するため、キャッシュなしの起動や物理的に独立した署名ホストの新たな実証ではありません。本番・IAM・既存保持設定は変更しません。


## 専用環境での検証記録

[公開用証拠](../../evidence-public/rbr-editor-reconstruction.json)を参照してください。実際にブラウザで3回編集した第3世代を、保存APIの反映完了応答から選びます。元のWordPressを終了し、元データとキット生成用フォルダを復旧処理から見えなくして、新規の非公開WordPressを2回作ります。別途定義した編集後Qと照合し、古い連絡先の期待値を与えた場合も、採取したDB・HTTP観測から拒否を確認します。

最初のキット生成は、新規キットのS3書込み・承認・WordPress起動より前に停止しました。異常検出テストを旧サンプルの電話番号に依存しない形へ変更した一方、Eは旧コードを固定したままだったことが原因です。差分は `tools/rbr-reconstruct-lab.py` だけでした。新しいEとして明示的に固定し、新規作業領域で再開しました。失敗記録は残し、試験基盤の設定不整合として区別します。署名・期限検査は緩めず、実行イメージの既存キャッシュを再利用します。

親の取得不能・期限切れはオフラインで検証し、実S3の親世代を削除・期限切れにはしていません。実取得では親を取得せず、参照自体は署名対象の世代内に保持します。選択世代の素材については保持期限を検査します。履歴全体の監査やキャッシュなし復旧の実証ではありません。
