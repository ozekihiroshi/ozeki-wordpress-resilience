# Milestone 1 独立復旧仕様

版数：0.2  
更新日：2026年10月18日  
基準：提供されたMilestone 1作業指示書 v1.0。詳細要求は原文を参照する。

## 実証する命題

元のWordPressサーバに一切アクセスせず、外部に保存されたRecovery Bootstrap、RAM、Recovery Setを使って、別のクリーンな環境へWordPressを復元できること。

対象は模擬企業案内サイト1件。正常な資産を用い、Cold Standbyと手動操作を許容する。模擬本番のWordPress、DB、ファイル、管理画面、本番用資格情報を遮断し、その後は元環境から情報を取得しない。

## 目標と対象外

RPOは24時間以内、RTOは24時間以内を目標とする。定常的な追加クラウド費用500円／月以下は研究目標とする。復旧成立の合否、性能目標、費用目標を別々に判定する。

AI分析、高度なPEM、完全自動復旧、マルチクラウド、自動DNS切替は実装しない。侵害済み資産からの安全な復旧と高度な信頼基盤の検証は後続段階とする。未実装の真正性保証は未検証として記録する。

## 必須情報と復旧資産

- DB、メディア、テーマ・プラグイン・独自コード、必要な構成情報と実行環境定義。
- RAM：サイト識別子、各ソフトウェアのバージョン、必須資産、取得先、S3固定バージョン識別子、完全性情報、依存関係、復旧手順の識別子。
- Recovery Set：DB・メディア・コード・構成の組み合わせを固定し、同じIDの内容を暗黙に差し替えない。
- Bootstrap：RAMと復旧手順の取得方法、復旧権限の取得手順、検証情報、緊急操作手順。

JSON等の可搬性の高い形式を採用し、スキーマバージョンを明記する。秘密情報は別管理とし、Bootstrap等にパスワード、アクセスキー、復号鍵を平文で埋め込まない。

## 合格条件

| ID | 条件 |
| --- | --- |
| AC01 | 元サーバへのアクセスなしで復旧できる |
| AC02 | BootstrapとRAMを独立して取得できる |
| AC03 | 必須復旧資産をすべて取得できる |
| AC04 | DBの基準データが復元される |
| AC05 | 対象メディアの完全性検査に成功する |
| AC06 | 定義した主要ページと機能が動作する |
| AC07 | E1・E2・E3の証拠を区別して保存する |
| AC08 | 復旧手順を再実行可能な形で記録する |

全条件を満たした場合に基本実証を成功とする。検査対象はDB基準データ、メディアSHA-256、WordPress起動、固定ページ、投稿、画像・PDF取得、内部リンク、管理画面ログイン、ダミーフォームを含む。具体的な期待結果は試験前に固定する。

## 証拠と測定

E1はWordPressやプラグインからの申告、E2は外部での資産存在・取得・完全性の観測、E3は独立環境での復元・動作検証とする。

各記録に証拠ID、種別、対象資産またはセット、実施日時、主体、方法、範囲、結果、関連ログを含める。E1のみで独立復旧成功を認定しない。失敗と未検証を区別する。

想定障害時刻、復旧開始・終了、復元データの時点、実測のデータ損失時間、サービス再開までの時間、実作業時間、再試行と失敗を記録する。RTO目標との比較では、障害発生から事業機能の再開が可能になるまでを対象とし、実作業時間と区別する。検知・対応待ち等を試験で含めたか明示する。

容量、計算資源利用時間、クラウド費用、人的時間を記録し、定常費・試験費・事故対応費を分離する。

## 作業上の制約

実運用サイト、DB、DNSに影響を与えず、既存S3オブジェクトを削除しない。本番用認証情報を実験コード・ログに残さず、個人情報や実顧客データを模擬サイトへコピーしない。

課金リソースの作成・変更は対象と概算費用を提示して承認を得る。既存の変更を破棄せず、強制pushや履歴破壊をしない。疑わしい環境や不明な認証情報を発見した場合は停止して報告する。

進行不能時は事実、未確認事項、実行コマンド、エラーを記録する。未実施の試験や未取得の証拠を完了と記録しない。

## 今回の試験条件の合意（2026年10月18日）

利用者は「今回は同一ロールで検証し、権限分離は未達として評価する」を選択した。Phase 3の独立した権限による取得という当初要件は削除せず、未達項目として残す。その状態でPhase 4の機能試験とPhase 5の評価まで進める。

復旧先は元環境と同じWSLホスト上の別Dockerプロジェクトで、新しいボリューム・ネットワーク・DB資格情報を使う。元WordPressのコンテナとDBは停止し、そのデータを読み取らない。ホストOSの侵害・完全喪失と別管理者による復旧の実証は後続課題である。

既存プラグインのDBダンパーを利用し、M1独自の収集索引を上位RAMへ組み込む。判断理由と既存製品との責任分担はADR 0003を参照する。合否はdocs/m1/10-milestone-1-evaluation.mdにまとめる。Phase 5の評価完了は、残存要件の達成や本番提供可能を意味しない。
