# 保存要求からのQ生成と世代への結合（試作）

新規に明示登録した3ページでは、保存要求を検査した直後にQを生成し、要求と一緒に固定します。タイトル・slug・平文段落は要求から、画像のハッシュ・寸法とページ間の関係は検証済みの登録原本から得ます。再構築したDB・表示結果・試験成功結果からQを作りません。Qの公開状態は復旧先の非公開draftを表し、保存元のpublishを引き継ぎません。

保存ジョブへQの `expected_sha256` を含め、既存コーディネーターが保存する不変の意図と、そのハッシュを持つ確定世代へ結び付けます。世代確定後、世代の固定参照・意図・Qを含む対応記録を、予約領域 `originals/request-expectation/<操作ID>/source` に新規固定版として保存します。この資産IDは登録できません。Q対応記録の保持期限が世代の約束を満たした後に、WordPressへ反映します。

Qの保管が失敗した場合、世代が確定済みでも公開内容は変更せず未完了にします。同じ操作から再開すると、固定した同じQ・世代を使用します。要求変更による同じ操作IDの流用は拒否します。Q保管前に要求台帳自体を失った場合の救出・旧台帳移行は今回の対象外です。

反映完了応答に `expected_ref` を追加しました。この応答を既存キット入口へ渡し、プロファイルには `owr-rbr-request-profile-v1`、site_id、固定したrules_ref/environment_ref/comparison_refだけを指定します。手動のexpected_refやrequired_scopeは指定しません。要求由来Qとの結合・保持を確認し、QとscopeをそのままDへ採用します。キットv2は対応記録を必須にし、取得後にもD・Q・世代との一致を再検査します。旧取得ツールはv2を拒否するため、新しい対応記録を無視して進みません。詳細なプロファイル例は[英語仕様](rbr-request-q.md)を参照してください。

**Qの自動生成は、独立署名承認の自動化ではありません。** 保存要求どおりの内容を再構築できるかという期待値であり、事業上の内容確認や署名承認は別です。鍵ピン・最新台帳・失効・有効期限・実行直前の再検査は変更せず、キットは承認待ちで止まります。従来のv1・手動Qキットは従来の条件で扱います。

## 検証範囲と制限

[証拠](../../evidence-public/rbr-request-q.json)：実WordPress HTTP・MariaDBと既存S3契約ダブルで32項目を確認しました。Q保管の失敗、公開内容保持、同じ世代・Qからの再開を含みます。実保存APIの第5世代から、手動Qなしで実PHP計画生成器がPと承認待ちv2キットを生成しました。Python回帰試験75件（PHP生成器の8項目を含む）も成功しています。Q改変・別世代・意図の不一致・手動Qの上書き・v2の対応記録欠落・保持不足を拒否します。

今回は実S3への保存や前回の2回再構築を繰り返していません。対象は固定画像・固定関係を持つ既存3ページと平文です。本文がすべて空白、編集後の段落外に関係が残る要求は拒否します。汎用Gutenberg、新規画像、Markdownは対象外です。Q情報のない旧登録・未完了台帳は、DBからQを後付けして移行したり初期化したりせず、別途移行設計が必要です。旧完了操作の応答は維持します。本番変更・自動公開はありません。

静的確認で意図とQの保存キー衝突の可能性を修正しました。その修正を適用するため、初回の依存コピー準備をコンテナ作成前に停止し、未完了フォルダを保持しました。環境障害ではなく、最終試験で新たな環境問題は発生していません。

## 要求由来Qによる実S3一貫検証（2026-10-23）

[実S3検証結果](../../evidence-public/rbr-request-q-live.json)。実際の保護対象編集画面から3世代を確定し、ブラウザ21項目に合格しました。保存失敗時の公開内容保持、競合・古い編集の拒否、S3確定後の中断と同じ世代からの再開を確認しました。適用済み応答の `expected_ref` を直接使い、手動Qは渡していません。再構築前に固定版の結合・要求ハッシュ・Qハッシュを検査し、実PHP計画器で9ステップの計画と独立承認待ちのキットv2を生成しました。

別のroot専用試験署名アカウントで承認し、既存の署名・鍵固定・最新台帳・失効・期限条件を維持しました。実際の復旧プロセスから元サイトとキット作成用フォルダをマウント分離で隠し、S3固定版から取得した素材だけで2つの新規隔離WordPressを再構築しました。両方が保存要求から固定した同一Qと一致し、誤ったQは拒否されました。選択資産とQ結合の保持期限を確認し、親世代は来歴として保持して取得していません。実S3の親資産を削除・期限切れにする試験は行っていません。

回帰試験75件も合格しました。専用コンテナ・通信規則を後片付けし、既存9コンテナは維持しています。本番変更・自動公開・承認延長はなく、今回の接続に新たな製品コード修正は不要でした。同一ホスト上の別署名アカウントとキャッシュ済みOCIイメージを用いた試験であり、物理的独立性やコールドキャッシュ復旧の実証ではありません。一般の投稿経路や旧登録状態の自動移行は未対応です。

試験基盤の問題：補助ハッシュ確認で日本語JSONをASCIIエスケープする設定になっており、製品のUTF-8正規化と不一致でした。補助処理を既存規則へそろえて解消し、保存データ・製品の検査・承認条件は変更していません。初回のWSLアクセス拒否はサンドボックス実行権限に起因し、許可済み実行経路で解消しました。WSL設定は変更していません。
