# 実S3の確定世代から署名付き再構築への入口

履歴上の区別：以下は受領票入口だけを検証した先行段階の記録です。その後の実コーディネーター接続は[実S3検証結果](rbr-live-coordinator-jp.md)で別途確認済みです。本番編集入口との接続は未対応です。

試作CLIです。`rbr-generation-kit.py`へ確定世代の固定参照、再構築プロファイル、新しい専用作業ディレクトリを渡します。試験データ生成処理を呼ばず、Dのassets_refを入力世代のまま保持します。本番保存画面への接続や自動公開は行いません。

プロファイルは`owr-rbr-definition-profile-v1`形式で、site_id、rules_ref、environment_ref、comparison_ref、expected_ref、required_scopeを明示します。assets_refや生成済みPの差替えは受け付けません。Qは生成結果から逆算せず、独立して選択します。

S3の固定版・サイズ・ハッシュ・保持情報に加え、世代の実保存時刻が確定期限内であること、protect_untilがdeadlineから35日であることを検査します。原本・世代とその参照先の保持がその期限に届かなければ停止します。選択した世代を黙って別のものに変えません。

R/E/C/Q側の保持が足りない場合は別キー・別版へコピーし、参照を末端から組み直します。新規オブジェクトだけ作成時に36日＋10分の保持を指定し、取得し直して世代の約束期限を満たすか検査します。既存版の保持変更、バケット設定変更、PutObjectRetentionは行いません。既存の35日用処理も変更しません。PHP世代確定コーディネーターの従来モードの36日デフォルト要件は残し、新規版へ明示的に保持を付けるモードを追加しました（rbr-live-coordinator-jp.md参照）。実験バケット自体にはデフォルト保持ルールがありません。

既存のローカル計画生成器でDを検査してPを生成し、実行コードとDを保存後、最後にルート受領票を確定します。状態は「保存完了・独立署名承認待ち」です。この受領票を既存の`rbr-approved-kit.py`へ渡します。公開鍵固定・最新台帳・署名・期限の条件は変更せず、承認の自動延長も行いません。

同じ作業領域の重複起動をロックで拒否します。同じ入力による再開では保存済み受領票を再利用します。結果不明PUTは再送せず停止します。入力変更は拒否し、別作業領域を要求します。

制限：既存実験バケット・SSH権限仲介専用で、汎用本番接続ではありません。Docker等の互換要件は従来どおりです。現在は過去の親世代・来歴の参照先も同じ期限までの保持を要求するため、古い参照の保持が足りない世代は拒否します。来歴を復旧依存物から分離する実装は未対応です。

実S3試験では試験用原本を固定版で確認してから世代マニフェストを保存します。この入口の受領票から先を検証するもので、PHP世代確定コーディネーター自身の実AWS同時実行・IAM試験ではありません。模擬S3の競合試験を実AWS実証へ読み替えません。

## 専用環境の結果

PASS：実S3固定世代の参照を取得後Dでも保持し、新しいルート受領票を既存の独立署名入口へ渡して、新規WordPress 2回ともQに一致しました。取得した全キット版の保持が世代の約束期限を満たし、結果不明PUTは0です。最終コードの確定時刻検査は保存済み実S3証拠から同じルートを再現し、追加PUTなしで原本世代を実S3から再確認しました。[検証記録](../../evidence-public/rbr-generation-kit.json)。これは受領票から再構築までの実証で、PHP世代確定器・本番編集入口の実証とは区別します。
