# 再構築定義と論理状態の比較契約 v1

2026年10月22日・仕様案。[英語主仕様](rbr-reconstruction-definition-v1.md)。[基本原則](immutable-assets-deterministic-reconstruction-jp.md)を既存のA形式に具体化した文書です。実装・試験・本番変更は行っていません。

## 1. 再構築定義DでA・R・Eを結ぶ

既存のサイト世代Aを書き換えず、別の不変な「再構築定義D」を追加します。同じAに別の規則・環境を組み合わせる場合も、新しいDを作ります。

| Dに含める項目 | 内容 |
|---|---|
| schema・site_id | 定義形式と元の独立サイトID |
| Aの参照 | サイト世代目録の固定Version ID、格納先、サイズ、SHA-256 |
| Rの参照 | 固定した規則ファイルの格納先・ハッシュ |
| Eの参照 | 固定した環境定義の格納先・ハッシュ |
| Cの参照 | 論理状態の抽出・比較規則と、その実装ができた時のビルド識別 |
| 必須範囲 | 会社案内・サービス・連絡先、含める画像、必須情報 |
| Qの参照 | 事前に独立して用意した期待結果の格納先・ハッシュ |

保存したDそのもののバイト列のSHA-256を定義識別子にします。自分自身のハッシュをD内部に入れる循環は作りません。S3の「最新」やインストール済みの既定値を参照して補完しません。

保持付きコピーで原本の内容が同じでも、参照先を書き換えたDは別定義です。「意味が同じ」と「入力定義が完全に同じ」を分けます。R・Eの実行物・C・Qも、Dが使える期間は保持が必要です。

実際の版・ハッシュがまだ決まっていない定義は、**未バインド・実行不可**と表示します。今回、実行物の版やダイジェストを架空の値で埋めません。

## 2. 初版R：会社案内のテキスト3ページ

規則名は`corporate-pages-text-v1`とし、内容のハッシュも固定します。

- 通常のWP固定ページを3つ作り、会社案内→サービス→連絡先を全体ナビゲーション順とする。会社案内を入口にする。
- 元のタイトル・slug・段落文字列と順序を保持する。slug重複は勝手な連番補正をせず拒否する。
- 本文はプレーンテキストとして出力する。HTML・ショートコード・埋込みを実行しない。Markdown変換は初版に含めない。
- 画像と内部リンクの`position`は「段落間の位置」と定義する。段落数Nに対し0は先頭、Nは末尾。範囲外は拒否する。
- 同じ位置は画像→リンクの順。同じ種類なら対象資産ID順にする。同一の重複辺は拒否する。
- リンク文字列は対象ページのタイトルを使い、リンク先は新サイトの資産ID対応から決める。アンカー・クエリー・外部リンク・文章途中への埋込みは現在の形式では未対応として明示する。
- `navigation`関係は、そのページの本文後に出す関連ページ一覧。全体ナビゲーションとは分け、同一ページの位置重複は拒否する。
- 現在のAに親子情報がないため、3ページはすべて親なしとする。

この規則に適合しない既存Aを勝手に修正しません。必要なら修正した新しい資産版・世代を作ります。現在の保存処理が受理したAでも、再構築規則への適合検査では止まる場合があります。

### 画像と公開状態

JPEG/PNGの原本ハッシュ・サイズ・寸法・形式を保持し、画像資産ごとに添付ファイルを1つ作ります。本文には原本を使用し、再生成したサムネイルへ黙って置き換えません。

現在のAには代替文・説明がありません。初版では、**装飾画像であると明示的に選んだ画像だけ**を空のalt・説明なしで扱います。情報を伝える画像を勝手に装飾扱いにせず、必要な説明がなければ未達として止めます。この選択は定義を作る時の判断で、毎日の承認は増やしません。

再構築直後は3ページを下書きとして管理者の認証付きプレビューで確認します。実際の下書き状態と、確認後に公開する意図を区別します。フォーム・決済・外部サービス・旧ユーザー移行は対象外です。連絡先は明示した本文の情報をそのまま保持します。

## 3. Eと配置時の値B

EにはWP、クリーンなテーマ1つ、必要な再構築プラグイン／エンジンF、PHP・拡張、DBの種類と版・文字コード・照合順序、言語・タイムゾーン、URL方針、画像処理系、空サイトの初期化手順を固定します。版名だけでなく実行物のハッシュと取得先も必要です。

移行先URL・配置パス・DB接続先・新規認証情報・実行IDなどはBとして別途明示します。秘密値は証跡へ書かず参照だけを残します。結果に影響する実行系や言語を「環境差だから」とBへ隠しません。

対象は空の新しいサイトです。旧DB・options・ユーザー・設定ファイルは投入しません。作業用管理者は初期化手順で明示します。既存の事業データを消して空にする処理は初版に含めません。

固定パッケージを準備・検査した後、外部通信・メール・決済・Cronを制限して計画を実行します。遮断されたものも含め、予期しない外部処理の試行を検出したら不合格です。必要時だけ環境を用意する構成でよく、常設の別EC2は要求しません。

## 4. 計画Pと実行記録

`P = plan(A,R,E)`は独立資産IDだけで、画像登録→3ページの枠作成→本文・関係の反映→ナビゲーション・入口設定→範囲確認という計画を作ります。画像は資産ID順、ページは役割順です。旧サイト、現在時刻、乱数、暗黙の外部設定を使って内容を決めません。

実行器が資産IDと新しいWPの内部IDを対応付けます。異なる資産を同じ対象へ割り当てたり、再開時に同じ資産を重複作成したりしない契約です。同じD/Pの途中再開と、入力を変えた別実行を区別します。

比較器は実行器の「作りました」という記録だけを信用しません。実際のDB・プレビュー・画像の応答から状態を読み取り、対応表も検証します。

## 5. 比較する論理状態C(W)

| 対象 | 必ず比較するもの |
|---|---|
| ページ | 役割、タイトル、slug、段落と順序、親なし、実際の下書き状態、画像・リンクの位置 |
| 画像 | 原本のハッシュ・サイズ・形式・寸法、実際に配信された原本のハッシュ、装飾画像としてのalt・説明 |
| 関係 | リンク文字列、解決された対象資産、全体／関連ナビゲーションの順序、会社案内への入口 |
| 網羅性 | 必須3ページと対象画像が全部あり、未解決参照や予期しない再構築物がないこと |
| 動作 | 認証付きプレビューで閲覧・リンク移動でき、未認証には下書きの事業情報を公開しないこと。禁止した外部処理がないこと |

許容する正規化は以下に限定します。

- DB内部IDは、検証済みの対応表で資産IDへ置き換える。
- URLは実際の遷移先を確認して資産IDへ置き換える。ホスト・クエリー・フラグメントを一律に削除しない。プレビュー用認証値も、動作を確認してから比較対象外にする。
- 指定した本文ノードの文字列を取り出し、HTMLエンティティを復号し、CRLFだけをLFにそろえる。段落・空白・句読点・意味のある改行を削除しない。CSSによる空白省略も隠れた欠落として扱うか、その入力を事前拒否する。
- 秘密情報、運用上の生成時刻、配置パスは内容比較から外せるが、意味のある公開日を勝手に除外しない。

比較用JSONはキー順・配列順・文字列の扱いを版管理し、整数だけを使って固定形式へ直列化します。ハッシュだけでなく、どの項目が違うかも出力します。現在のPHPのキー整列を、そのまま全言語共通の標準として扱いません。

テーマ装飾のピクセル単位の一致、任意サムネイルのバイト一致は初版の合格条件外です。その代わり、必要な本文・原画像・関係・動作は比較から外しません。

## 6. 期待結果Qと合格条件

Qには、正しいタイトル・本文・段落順、画像ハッシュと寸法、リンク位置と表示文字列、ナビゲーション順、必要な連絡先、下書きプレビューの状態を事前に記載します。

試験データの案は「Example Company」「Services」「Contact」、明示した会社説明・サービス文、`contact@example.invalid`と`TEST-0001`という架空連絡先、装飾用の生成PNG1枚です。実際の文字列と画像ハッシュは、試験素材を作る段階で固定します。今回既存fixtureを変更したわけではありません。

Qを計画生成器・描画処理・比較器そのものから作って正解扱いにしません。最初は独立して作成・確認した期待値を使います。

**合格条件は `C(W1) = C(W2) = Q` に加え、網羅性と副作用制限の合格です。**

同じD/A/R/E/C/Qを使い、二つの空環境を独立に準備します。片方のDBや生成物・キャッシュをもう片方へ使い回しません。移行先URL・内部IDの割当てだけは許容範囲で変え、正しく対応できることを確かめます。旧サイトへの接続はできない状態にします。

比較器自体の確認として、連絡先1文字変更・画像欠落・リンク先入替え・段落順入替えは必ず不合格とし、正当な内部ID／移行先URLの違いは対応確認後に合格とする計画です。長期観測を再開するものではありません。今回は実行していません。

証跡には定義・計画・比較器のハッシュ、環境照合、秘密を除いたB、観測原文と正規化結果、Q、差分、欠落、副作用の観測を残します。証拠不足を成功扱いにしません。再現性の合格と本番公開の判断は別です。
