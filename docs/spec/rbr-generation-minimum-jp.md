# S3先行保存・世代確定の最小実装と検証

2026年10月22日・試作版。[英語版](rbr-generation-minimum.md)／[検証記録](../../evidence-public/rbr-generation-minimum.json)。

## 今回実装したこと

既存のVersionedAssetStoreを変更せず再利用し、固定Version ID・ハッシュ検証の上に、原本保存と世代確定のPHP部品を追加しました。

- 操作IDと変更内容をS3上の不変な処理記録に固定。
- 会社案内・サービス・連絡先、画像、関係、Profileを保存・照合し、そろった時だけ連番の世代目録を条件付きで確定。
- 同時編集では一方だけが確定。既存世代を上書きしない。
- 一部保存や応答消失では保存結果を照合し、同じ操作から再開。送信済みのローカル素材がなくても再利用可能。
- 保持期限が足りない画像は固定版から取得し、同じ内容の保護付きコピーを新しいキーへ保存。保持変更・削除APIは呼ばない。
- 締切後に確定した場合や保持条件不足は、オブジェクトが存在しても正常完了として返さない。

これは開発キットの処理部品です。WordPressの通常更新ボタンやDB反映にはまだ接続しておらず、結果は`wp_state: not_applied`です。

初期入力は、3ページのタイトル・slug・プレーンテキスト段落、JPEG/PNG、リンク・画像・ナビゲーションの型付き関係、役割Profileに限定しました。HTML変換、見出し・アンカーの変換、動的ブロック、レイアウトや新WPへの再投入は含みません。構造の未対応項目は拒否します。画像は形式・寸法を調べ、原本を保持しますが、完全なデコード検査や無侵害判定ではありません。最大16資産、各8MiB、合計64MiB、1000世代の試作上限があります。

## 検証した範囲

**専用一時領域と生成データ、ローカルのS3契約テストダブルで21項目が合格**しました。既存PHP・配布試験を含む13回の試験実行も合格しています。

二つのPHPプロセスを実際に同時実行し、確定が一つだけになることを確認しました。ほかに、一部保存失敗、保存・確定応答の消失、アクセス拒否、ハッシュ不一致、期限不足、コピー失敗、再開時の重複防止、締切超過、時刻差、未解決リンクを検証しました。試験用一時領域は削除済みで、結果とソースハッシュを保存しました。

```sh
php tests/test-rbr-generation.php
```

依存ライブラリを用意したPHP 8.1以上、GD・pcntlが必要です。外部通信やAWS認証情報は使用しません。

**実AWSのS3やIAMでの検証は今回行っていません。** 条件付き作成・Object Lock・権限強制を実AWSで確認済みとは扱いません。

## 実S3試験用の入口

`tools/rbr-save-lab.php`にAWS SDK接続を用意しましたが、今回実行していません。明示的な`--execute-lab`、`synthetic-lab`設定、`owr-rbr-lab-*`バケット名に限定します。バージョニングと36日ガバナンスのデフォルト保持を要求し、既存の35日設定を変更したり、そのまま代用したりしません。バケット作成・IAM変更・削除機能はありません。

`tools/rbr-create-fixture.php`で会社案内の生成素材とjob.jsonを作成できます。実行方法は英語版に記載しました。失敗・結果不明の再開では、新しいjobを作らず同じ操作IDと内容を使います。保存済み世代の次を試す場合だけ、成功結果から新しいjobを作ります。

## 未達と問題の区分

- プラグイン側：S3保存部品は今回実装。WP保存入口・DB反映・管理画面・再構築・独立した利用保留確認・履歴の自動探索は未実装です。インストール用管理画面ZIPには組み込んでいません。
- 試験基盤：ファイルシステムでS3の契約を代替しているため、IAMと実際の保持強制の証拠にはなりません。これは残っている接続検証です。
- 環境：通常権限のWSL呼出しがツール権限で拒否されましたが、承認された実行では正常に動きました。プラグインの障害とは区別します。
- 実装中の修正：サーバ保存時刻を追加した際、初回と再開の受領記録の配列順が違ったため統一し、試験を再実行しました。最終記録に未解決の試験失敗はありません。

本番・既存S3・署名承認・共通部品・短縮観測の結果は変更していません。常設別EC2の作成、公開、GitHubへの反映は行っていません。
