# 再構築定義の検査・計画生成の最小実装

2026年10月22日・開発キットの試作機能。[英語版](rbr-planner-minimum.md)／[検証記録](../../evidence-public/rbr-planner-minimum.json)。

## 今回できたこと

`RbrReconstructionPlanner`に、DからA・R・E・C・Qと環境パッケージの固定参照をたどり、サイズ・ハッシュ・形式・必須項目を検査する処理を実装しました。既存のサイト世代形式とJSON直列化処理を再利用しています。

保存済みAであっても、再構築に必要な3つの役割、slugと資産IDの一意性、Profile対応、必須の連絡先、画像、関係先・配置位置を改めて検査します。未対応項目や情報不足を黙って捨てません。原本を書き換える処理はありません。

画像1枚の試験用サイトでは、次の9指示を含むPを生成します。

- 画像登録：1指示
- 会社案内・サービス・連絡先の下書きページ作成：3指示
- 各ページの本文・画像・リンク・関連ナビゲーション反映：3指示
- 認証付きプレビューの入口と全体ナビゲーション設定：1指示
- 必須範囲・非公開・外部副作用禁止の確認：1指示

**これはJSONの計画であり、WordPressへ指示を実行してはいません。** 計画には移行先URLやWP内部IDを埋め込まず、実行時に対応付ける独立資産IDを使います。現在時刻や乱数、旧サイトの状態によって内容を決めません。

計画部品と既存の直列化部品を束ねた実ソースのハッシュもEのエンジン参照と照合します。実行中に設置コードを変更しない前提のビルド照合で、独立した署名認証ではありません。

## 専用環境での検証

生成データのAを既存の保存部品とローカルS3テストダブルで作り、**20項目が合格**しました。既存試験を含むPHP・配布関連の14回の実行も合格しています。

- 別々のPHPプロセスから同じDを読み、同じPがバイト単位で得られる。
- 元の入力ファイルを消しても、保存済みの参照素材だけで計画を作れる。
- キャッシュの並び順や無関係な追加ファイルで結果が変わらない。
- 参照欠落・ハッシュ不一致・可変な版指定・未対応規則・slug重複・不明な関係先などで止まる。
- 必須の連絡先や画像の意味付けを省略できない。
- Qに誤った期待タイトルを書いても、それをページ生成指示へコピーしない。
- 既存の計画出力を上書きせず、検査失敗時には計画を出力しない。

## 結果の限界

今回確認したのは**同一入力から同一の計画Pを作ること**です。Wはまだ作っていないため、「再構築したサイト2つが期待結果と一致した」とは扱いません。

EのWordPress・テーマ・PHP・DB・比較器は、版とハッシュを固定した非実行の試験用データです。実際のパッケージの起動・互換性・安全性は確認していません。実エンジンのソースはハッシュで結び付けていますが、出力は常に`execution_authorized: false`です。

Qは形式・対象範囲・参照内容を確認しますが、正解を計画へ流用しません。実サイトからの状態抽出とQとの比較は次の実装です。ローカルキャッシュ読取りでは、実S3にその版が存在することや保持・IAM・侵害保留情報は確認しません。

## 実行方法

新しい専用フォルダを指定し、開発キットから実行します。生成側はComposer依存関係、PHP 8.1以上とGDが必要です。計画CLI自体はAWS SDKやWordPressを起動しません。

```sh
php tools/rbr-create-plan-fixture.php --output=/private/new-plan-fixture
php tools/rbr-plan.php --definition=/private/new-plan-fixture/definition.json --objects=/private/new-plan-fixture/cache --output=/private/plan-one.json
php tools/rbr-plan.php --definition=/private/new-plan-fixture/definition.json --objects=/private/new-plan-fixture/cache --output=/private/plan-two.json
php tests/test-rbr-planner.php
```

定義JSONは既存の`owr-json-v1`直列化形式に限定し、重複キーや未知のフィールドを拒否します。入力ごと8MiB、JSON2MiB、参照素材合計64MiB、16資産・関係1000件までの試作上限です。`SYNTHETIC-ONLY.txt`を付けた生成物を、本番用復旧キットと混同しないでください。

最終検証で未解決の失敗はありません。環境・試験基盤の制限は上記のローカルキャッシュと非実行パッケージであり、プラグイン側の未達はWP投入器、状態抽出・比較器、実行時の副作用制御などです。本番・既存S3・署名承認・短縮観測は変更していません。GitHub反映や公開も行っていません。

実装の続き: [専用WordPressへの投入と比較](rbr-wordpress-reconstruction-minimum-jp.md)。
