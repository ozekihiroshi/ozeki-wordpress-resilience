# 3固定ページの保護保存API（試作）

[英語仕様](rbr-wordpress-save.md)を主とします。今回は実際の保存APIから既存世代確定器を呼び、確定した原本をWordPressへ反映する部分を実装しました。通常の管理プラグインから自動的に有効にはしません。署名承認・失効・期限の条件は変更しません。

## 今回の動作

認証済みの `POST /owr-rbr/v1/save` へ操作ID、期待する適用済み世代番号、会社案内・サービス・連絡先の3ページのタイトル・slug・平文段落を渡します。全対象の編集権限と固定ページ公開権限を必要とし、通常のCookie認証にはWordPress nonceを使います。クライアントからファイルパス、保存先、対象DBのID、期限を指定することはできません。

専用のInnoDB状態行に入力のハッシュと操作を記録してから、DBトランザクションを終了してS3保存へ進みます。未解決の操作があれば別の操作は受け付けません。既存コーディネーターで確定した後、その固定原本を読み直して表示用本文を作り、専用mysqli接続で状態行と3ページをロックします。世代・操作・従来ページのハッシュを再確認し、3ページと適用済み世代を一つのトランザクションで更新します。この接続は切断後の自動再接続・SQL再実行をしません。

- S3保存失敗：公開内容を変更しない。同じ操作で再開する。
- S3確定後の停止：同じ操作を固定版と照合して再開する。
- DB更新途中の停止：未確定の3ページ変更を巻き戻す。
- DB反映後の応答喪失：同じ操作の適用記録を返す。
- 競合・古い世代：拒否する。過去の完了操作を再送しても、当時の受領情報を返すだけで再適用しない。

## 明示する制限

既存の公開済み・親なし3固定ページが対象です。新規作成、削除、予約公開、公開状態変更、通常投稿、Markdown、任意ブロックは未対応です。画像と関係情報は初期登録済み原本を再利用し、画像ファイルがS3の内容と一致するか確認します。アップロード入口・新規添付作成は未対応です。

任意の保存フックの副作用までDBで巻き戻せると仮定せず、今回の反映は限定したSQL更新です。リビジョン、SEO等の保存フック、永続オブジェクトキャッシュは未対応です。通常エディターの更新ボタンへの接続はまだありません。

対象IDへのコアREST変更は自動保存・リビジョン経路を含めて拒否し、無関係なページは通常どおり更新できます。Classic、admin-ajax、XML-RPC、WP-CLI、直接SQL、任意プラグインの変更を全て封じるものではありません。保護対象が外から変わっていれば次の保存時に差異として拒否します。

管理者が専用テーブル・対象ID・素材・画像対応・非公開作業領域・ストアを明示的に準備し、登録する必要があります。APIから登録状態をリセットできません。試作台帳の上限は100操作です。期限切れ・終了不能操作の解消、整理、運用状態画面は未対応で、未解決操作を勝手に消して次へ進めてはいけません。

## 先行した模擬S3試験の範囲

専用WordPressの実HTTP REST APIとMariaDBを使用し、S3側は既存の永続ファイル型契約ダブルを使います。確定失敗、S3確定直後のPHPプロセス終了、DB更新途中のプロセス終了を注入し、反映・再開・競合を確認します。今回の結果を実AWSでの新しい一貫試験とは扱いません。実S3コーディネーターの前回証拠とは区別します。本番変更、AWS権限変更、外部通知、承認延長、自動公開は行いません。

## 実S3への保存・反映の一貫検証（2026-10-23）

同じ保存APIを、既存の限定SSH/S3通信処理へ接続し、実WordPress HTTP・MariaDB・実S3で25項目を確認しました。API・世代確定処理の本体変更は不要でした。これは専用試験の接続であり、本番用コネクターや通常の編集画面への組込みではありません。

新しい保存範囲が空であることを読取り専用で確認して開始しました。世代確定PUTを送る前の意図的な503では公開ページの全行が変わらず、同じ操作で再開できました。S3確定後のPHP停止では同じVersion IDから再開し、DB更新途中の停止では全ページがロールバックされました。競合要求・古い世代・同一操作IDでの内容変更を拒否し、完了済みの古い操作を再送しても最新内容を上書きしませんでした。確定した世代は4件で、反映した本文を非公開のHTTP接続で確認しています。

WordPress・MariaDBは外部通信なし・公開ポートなしです。専用Unixソケットを経由し、ホスト側で今回の実験範囲に限定した通信だけを行います。AWS認証情報はWordPressへ渡しません。新規オブジェクトの既存36日保持方式を利用し、バケット設定・既存保持・IAMは変更していません。専用コンテナは撤去し、証跡とS3固定版は保持します。意図的な障害注入を、実際のAWS障害や発見されたプラグイン不具合と混同しません。

[実S3の証跡](../../evidence-public/rbr-wordpress-save-s3.json)。以前の模擬S3試験は別証跡のまま残します。通常の編集ボタン・画像アップロード・投稿・Markdown・未解決操作の取消しは未対応です。現在のAPIは同期式で、試験用通信は要求ごとにSSHを往復するため、編集画面の応答時間を合格とする試験ではありません。署名・期限などの再構築承認条件は変更せず、今回は再構築の再試験ではなく保存元WordPressへの反映を検証しました。
