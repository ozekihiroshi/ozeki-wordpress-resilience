# 同一サーバー復元の共通実行条件

[English](same-host-runtime.md) | 日本語

準備・検査・既存復元workerの不整合を、WordPress/MariaDBの2コンテナ構成で解消する変更です。一般サイト向けリリース、自動承認、クラウド環境構築ではありません。

## つながる処理

共通のsame-host-runtime.pyで、環境作成引数と検査条件を管理します。same-host-preflight.pyも新形式owr-same-host-wordpress-pair-v1なら同じ検査を呼びます。最初の単一コンテナ形式は独立した診断用で、WordPress復元の実行条件ではありません。

既存の署名・最新台帳・固定版・内容確認を通過した後、復元処理は次の順に進みます。

1. イメージIDを固定し、停止状態のDB/Webコンテナを準備する。
2. runtime-config.jsonを保存し、両コンテナの条件を検査する。
3. DBを起動し、SQL投入直前に再検査する。
4. WebをそのDBの閉じたネットワーク名前空間で起動し、ファイル投入直前に再検査する。
5. 既存のSQL・ファイル復元、投稿・画像・HTTP確認を行う。
6. 既存の結果記録・日次登録・所有資源の後片付けにつなぐ。

段階はprepared/db_started/runningに分けます。検査結果と拒否理由はisolation.jsonに記録します。DB等が終了した場合は、待機期限まで放置せず起動失敗とします。準備と検査は同じローカルDockerソケットを明示して使います。

## 初期化に必要な権限と、維持する制限

公式イメージはコンテナ内rootによる初期化・所有者設定を必要とします。そのため65534固定の単一コンテナ条件をそのまま使わず、別の明示した実行契約にしました。無制限な権限を許す変更ではありません。

- rootファイルシステムは読取り専用。本番マウント・永続volume・デバイス・Dockerソケットは禁止。
- capabilityを全除去し、初期化に必要なCHOWN/DAC_OVERRIDE/FOWNER/SETGID/SETUID/NET_BIND_SERVICEだけ許可。no-new-privilegesを必須化。
- DBはnetwork none。WebはそのDBの完全IDを指定して共有。公開ポート・追加ネットワーク等は禁止。
- 資格情報は試験用に新規生成。既存のWordPress Cron・外部HTTP・ファイル変更の停止も維持。外部通信はネットワーク分離でも防止。
- 各コンテナ：メモリ1GiB、swap込み上限も1GiB、CPU0.5、PID128。自動再起動・自動healthcheckなし。Dockerログにも1MiB×2の上限。
- DBデータとWebファイルは各512MiBのtmpfs。/tmpと実行用ディレクトリは32MiB、Apacheログ・ロックは各8MiB。noexec/nosuid/nodevを指定。
- MariaDBの/run/mysqldを準備時に明示する。
- 準備検査はホストの利用可能メモリ2GiBとディスク空き1GiBを要求する。専用試験向け値で、予約や一般サイトの必要量保証ではない。

ホストroot/daemon侵害、管理者による同時変更、悪意あるコードによるカーネル攻撃への保証ではありません。強制停止時は従来の中断資源確認・明示cleanupが必要で、自動回収完成とはしません。

## 今回の範囲と残課題

承認・失効・期限の処理は変更しません。試験台帳は専用/run領域へテスト内だけで向け、本番台帳を変更しません。試験用署名とローカル固定版ストアを使います。

元の復元処理にある生成サイトの制限、実験用サイズ、特定投稿・画像の確認は残っています。production_paths=[]は本番領域を使わずマウントを全面禁止する生成試験の設定です。一般サイト向けには実際の対象・作業領域を導入時に検査する契約が必要です。

棚卸しで指摘した実行条件の不整合はこの専用構成で対応しますが、一般化した取得/保管接続、一般サイトの内容検査、侵害凍結・隔離、キットからの環境構築は引き続き未完成です。

## 2026年10月22日の検証結果

[検証記録](../../evidence-public/same-host-runtime.json)：導入検査・実行条件22件、最新信頼情報28件、復元worker10件、後片付け11件が成功。一貫試験8項目も成功し、条件不足時の拒否、重複防止、取得、固定版保管、試験署名・最新台帳、隔離復元、結果登録、資源回収を確認しました。復元中は取得元の作業領域を利用できない状態です。Docker・WordPress・MariaDBは実物ですが、保管はローカル代替であり、実AWS往復試験ではありません。

途中の3回の失敗も記録を保持しています。DockerのCAP_表記、tmpfs設定後の/run/mysqld不足、localログのmax-file=1非対応は、今回の実行条件の実装不整合として修正しました。原因不明の環境問題には分類しません。承認条件は変更していません。
