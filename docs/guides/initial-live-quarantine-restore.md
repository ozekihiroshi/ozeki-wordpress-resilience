# wp.ceri.link 初回データの隔離復元

実施日：2026年10月18日。初回取得物を外部通信できないローカル環境へ復元し、下記の範囲で確認に成功した。

[公開集計](../../evidence-public/initial-live-quarantine-restore.json) / [取得方法](initial-live-stream-capture.md)

## 構成と実行前チェック

取得済みのDB・サイト・実行イメージの容量とSHA-256を照合した。PCの既存署名鍵と独立ピンを照合し、有効期間1日の隔離検証専用承認に署名して検証した。この承認はオフライン試験用であり、正式なS3 RecoverySetの受入や無感染の認定ではない。秘密鍵はコンテナに渡していない。

DBはDocker network none、WordPressはそのネットワーク名前空間を共有する。公開ポートはなく、両者はループバックだけで接続する。実際のインターフェースがloのみであること、外部IP・EC2メタデータIP・DockerブリッジIPへのTCP接続が失敗することを確認した。

新規専用ボリュームとDBユーザーを作成し、サイト由来の接続資格情報を再利用せず、復元したwp-config.phpを試験用設定へ置換した。cron、自動更新、外部HTTP、メール送信を停止。Dockerソケット・元サーバーの領域をマウントせず、no-new-privilegesとCPU・メモリ・プロセス数の制限を付けた。DBは新規DBだけに権限を持つユーザーで取り込んだ。

## 結果

| 確認 | 結果 |
| --- | --- |
| 設定差替え前のファイル | 15,343個、全SHA-256一致 |
| WordPress起動前のDB | 12テーブル、計409行、取得SQLのテーブル別行数と一致 |
| トップページ | HTTP 200、タイトル要素あり |
| 公開ページ | 2件、正規URLのパスでHTTP 200、タイトル要素あり |
| 公開投稿 | 0件 |
| 添付登録 | 4件 |
| uploads内の画像等 | 派生サイズを含む23ファイル、HTTP 200、応答バイト列のSHA-256一致 |
| 外部HTTP・メール・cron | 遮断・停止を確認 |
| 終了状態 | 専用DB・WordPressとも停止、公開ポートなし |

最初の照合はSQLのVALUES後の改行を扱えず0行と誤集計した。検証器を修正して再照合した。DB再起動時は固定時間待ちで接続に失敗したため、ヘルスチェック待ちへ修正した。ページID指定のURLでは正規URLへの転送が生じたため、正規URLのパスを取得し、接続先を127.0.0.1に固定して確認した。外部への転送追従は行っていない。
