# 導入前検査・独立watchdogのZIP候補

今回の候補は `0.1.0-dev.1` の試作版です。正式リリースや72時間観測の合格判定とは分けます。候補ディレクトリーは `dist/candidate-20261021-preflight-validated`、同梱manifestのSHA-256で識別します。過去の候補ZIPは上書きしません。

## 含む機能と境界

WordPress用ZIPは導入前検査の結果、未確認項目、取得失敗、情報の古さ、および検査側・受渡し側の独立watchdogの状態・警報/回復履歴・転送状態を読取り専用で表示します。既存の日次状態・通知設定も保持します。

外部ホストの読取り専用棚卸し、SSH取得、導入前検査、独立監視、定期転送、systemd例は別の開発キットに含みます。WordPressへアップロードするのはプラグインZIPだけです。プラグイン更新だけで外部サービスは配置・更新されません。

## 新規導入・更新の確認

WordPress管理画面からZIPを導入・置換した後、「導入前検査」と「導入前検査の独立監視」を開き、対象サイト・monitor_id・取得時刻を確認してください。設定がない場合や情報が古い場合は、導入可能・正常とは扱いません。

更新前後に通知設定、Cron、wp-config.php、外部の報告・警報台帳・未配送記録を比較してください。無効化と削除は別の操作です。外部設定・鍵・台帳をプラグインフォルダーへ移動せず、コード更新時に空の状態ディレクトリーで置き換えないでください。

## 検証方法と制限

`tools/run-preflight-zip-lab.py` は隔離したWordPress/MariaDB/Chromiumで、新規導入と前回の状態報告候補からのZIP置換を、実Plugin_Upgraderで実行します。同じ開発版番号の置換であり、バージョン更新通知やブラウザのZIP選択操作を試すものではありません。

非デフォルトの通知設定をブラウザから保存し、更新・無効化・再有効化後の設定/Cron、wp-config、要求ファイル、外部台帳と報告のハッシュを比較します。導入された全ファイルを最終ZIPと照合し、両画面の表示・未確認項目・警報/回復履歴・編集者拒否・POST405を確認します。表示用時刻は各試験開始前に明示的に更新した生成データです。保持比較中には変更しません。

実SSHとsystemd停止・OS再起動は以前の専用VM試験を参照します。今回のZIP試験は本番適用、外部サービス全体のコード切替、実S3や実端末通知の再試験を含みません。72時間観測の欠測や未達をこの試験で補いません。
