# 共通隔離条件と実験用S3の一貫検証

[English](same-host-s3-roundtrip.md) | 日本語

## 今回新しく確認する接続

準備・検査・復元の共通2コンテナ条件を、既存の実S3アダプターへ接続します。生成WordPressの取得、SSH棚卸し、日次保存、別の試験署名、最新台帳検査、復元worker、結果登録を再利用します。承認条件と本番設定は変更しません。

専用ハーネスはtools/same-host-s3-roundtrip-cases.pyです。従来のローカル往復試験に既存のSSH/S3接続を渡します。最新台帳は専用/run領域のroot所有試験データです。鍵をコピーせず、既存SSH設定を通して実験用認可を受けます。保存はmy-ssm-role、読取りはOwrM1RecoveryReader、保管先は既存の実験用Object Lockバケットです。

## 合格条件

- 条件不足・重複要求で追加取得やS3書込みが起きない。
- 生成DB・ファイルの2資産を、空でないVersion IDと実際の保持証拠で保存する。
- 未承認・不正署名の経路ではリモート取得・復元を開始しない。
- 保存確認・承認確認・復元のGET台帳が同じ2つの固定版を指す。
- 取得元の作業領域が利用できない状態で復元する。
- 起動前・DB投入前・ファイル投入前の共通検査を通る。
- 投稿・画像ハッシュ・HTTP確認、日次restore_verifiedへの登録、所有するローカル資源の回収まで成功する。
- S3の保持対象は削除しない。

小規模な生成サイトの実証です。一般サイト対応・別物理ホストでの検証・限定SSH取得の完成を意味しません。保持・署名は無侵害の証明でもありません。過去の環境・試験基盤の課題や終了済み短縮観測は、今回の成功で上書きしません。
## 結果：2026年10月22日

9項目すべて成功。2資産合計29,811,484 bytesを2 PUTし、保存確認・承認確認・復元の計6 GETが同じ固定Version ID・サイズを参照することと、実際のGOVERNANCE保持証拠を確認しました。結果不明PUTは0です。隔離条件の3段階検査、投稿・画像・HTTP確認、結果登録recorded、日次状態restore_verified、所有するローカル試験資源の回収まで完了しました。同じ復元要求の再投入で追加転送・復元はありません。

[固定版・保持情報・実装ハッシュを含む検証記録](../../evidence-public/same-host-s3-roundtrip.json)。今回、新たな環境障害、予期しない試験基盤障害、製品不具合は確認されませんでした。接続用の専用ハーネスを追加しただけで、製品の復元・承認処理に追加変更は不要でした。前回の隔離実行条件の不具合と修正は前回記録に残します。無侵害や本番復旧承認を意味する結果ではありません。
