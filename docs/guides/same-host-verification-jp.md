# 同一サーバー検証：優先1の導入検査と設定

> 更新：この単一コンテナ検査は診断用です。既存復元処理との接続は[2コンテナの共通実行条件](same-host-runtime-jp.md)を参照してください。

[English](same-host-verification.md)

今回の実装は、設定とローカルDockerの実際の状態を読む導入検査です。**復元を開始する機能・一般的なインストーラー・承認ではありません。** 既存の署名承認・期限・最新台帳の条件は変更していません。

## 対応する最小構成

Linux、Python 3、/proc/meminfo、/usr/bin/dockerとローカルの/var/run/docker.sockを使います。リモートDocker contextは使いません。Dockerへのアクセス権は強いためWordPress/PHPへ渡さず、試験コンテナにもソケットを渡しません。ホスト管理者とDocker自体を信頼する前提で、ホスト侵害に対する独立検証ではありません。

[設定例](../../examples/same-host-verification/config.example.json)をWeb公開領域外へ用意します。秘密のDBパスワードや署名鍵は入れません。完全な停止済みコンテナID、ローカルイメージID、本番のファイル・DBの全パス、必要容量と予備容量を指定します。未設定のID例は拒否します。

作業領域は事前に作成された実行者所有0700のディレクトリとし、本番パスとの包含・重複・シンボリックリンクを拒否します。検査はファイル作成・権限変更・コンテナ起動をしません。準備はこの段階では管理者の操作です。

隔離条件は、非rootの65534:65534、root領域読取り専用、全capability除去、no-new-privileges、network noneかつ実接続先もnoneのみ、全マウント禁止、共有ホスト名前空間禁止とします。Dockerソケット・本番DBやファイル・外部通信経路を持ち込めません。再起動設定やhealthcheckも禁止します。

CPU・メモリ・swapを含む上限・プロセス数を設定と照合します。/tmpと/workだけをサイズ制限付きtmpfsとし、rw,nosuid,nodev,noexec,size=指定バイト数,mode=1777に限定します。二つのtmpfs上限の合計はコンテナのメモリ上限未満にします。

この厳しい最小構成は、データvolumeを宣言するイメージや稼働中DBサービスを許可しません。今後の復元処理が、この隔離条件内で適切なランタイムを用意する必要があります。既存の復元入口は接続・迂回していません。

## 実行と読み方

    python3 tools/same-host-preflight.py --config /private/same-host.json

終了コード0は専用試験へ進むための検査合格、2は拒否です。JSONに理由コード、設定ハッシュ、same_host、独立検証false、復元開始false、承認変更falseを返します。合格を「復元成功」「本番適用可能」とは表示しません。

必要作業容量は展開後の資産を基に指定します。圧縮サイズだけでは不足します。実空き容量が必要容量＋予備容量以上、現在利用可能なメモリがコンテナ上限＋ホスト用予備以上か確認します。例の数値はサイトの必要量を保証しません。

これは予約ではなく、その時点の読取りです。他処理との競合、後続取得のディスク上限、同時数、実行時間は今後の実行入口で制御が必要です。設定・コンテナが検査後に変わる可能性もあるため、実行直前のID・ハッシュ・資源再検査が必要です。古い合格結果だけで起動してはいけません。

## 専用環境での検証

単体13テスト成功。不適切設定の複数パターンを含みます。実Docker・生成データでは10項目成功：

- CLIが停止済みコンテナや設定ファイルを変更しない。
- 非root実行、root領域への書込み拒否、通信インターフェースがループバックのみ、制限tmpfsへの書込み。
- 本番相当の生成領域、Dockerソケットのマウントを拒否。
- 追加ネットワーク接続、メモリ無制限、root実行を拒否。
- 利用可能メモリ不足を注入して拒否。
- 実空き容量を超える必要量の指定を拒否。
- 本番相当の生成データが不変。

試験用に作ったコンテナだけを回収します。不適切なコンテナは起動しません。既存観測・本番・S3・鍵・FTP・MySQLは変更していません。

初回試験ではNetworkModeだけを見ると追加接続を見落とす**製品側の検査不備**を発見しました。実接続先も検査するよう修正し、単体回帰と実Dockerで確認済みです。環境のタイムアウトではありません。新たな環境阻害は観測していません。メモリ不足は注入試験であり、実機を枯渇させていません。WordPress実復元、メール送信、決済、長時間負荷の検証結果ではありません。
