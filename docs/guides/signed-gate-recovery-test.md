# 必須署名検証を通した独立復元試験

実施日：2026年10月18日。結果：合格。[公開用試験記録](../../evidence-public/signed-gate-recovery.json)。

## 対象と方法

RS-M1-LIVE-20261018-001の正常な既知の模擬資産を使用した。以前にS3から固定Version ID指定で独立取得したファイルを再利用し、今回はS3再取得を行っていない。手元PCの独立保管した公開鍵・信頼ピン・承認記録・署名を必須引数として、現在のtools/run-independent-recovery.pyから復元した。承認世代1、有効期限2026-10-25T01:45:40Z。コードは未コミットの開発作業ツリーを含むため、実行した入口と検証ツールのSHA-256を公開記録へ保存した。

署名・期限・世代・対象・独立承認ハッシュと展開済みBootstrapの一致を確認してから、固定資産のハッシュ照合、Dockerイメージ読込み、コード・メディア展開、DB投入、WordPress起動・機能検証へ進んだ。実行前のverify-onlyと、通常復元内の必須ゲートの両方が成功した。

## 実測結果

- 元サイト・元DB・元previewは停止したまま、元データを参照せず復元した。
- 新しいowr-signed-e3-1プロジェクト、新規DB/siteボリュームを使用。実際のマウント名が新プロジェクトだけであることも終了後に確認した。
- DB・ファイル等16項目が合格。DB基準データ、メディア一覧、ID、環境の4分野を元基準と厳密比較した。
- HTTP14項目が合格。主要ページ、日本語・絵文字、内部リンク、画像・PDF、フォームのnonce拒否・受付、管理者ログイン・プロフィールを確認した。
- 復旧ネットワークはinternal、プレビューはlocalhost限定。マルウェアに対する隔離性能の試験ではない。
- 復元本体は97.85秒（署名ゲート成功後から機能検査・独立性確認まで）。一時停止・署名ゲート・復元・今回の試験環境停止を含むrunner終了までの計測は104.44秒。

この時間は取得済み資産と準備済みDocker環境からの計測で、障害検知、判断、S3取得、基盤準備は含まない。過去の初回RTOと測定範囲が異なるため、速度改善や製品RTOとして比較しない。

## 終了状態

今回の3コンテナは停止済み。新しいボリュームと非公開試験記録は残している。同じ18081ポートを使用していた以前のowr-m1-e3-2だけを一時停止し、終了後に3コンテナを再起動した。DB/WordPress healthyとホームページの200応答・期待文字列を確認した。他プロジェクトのサービス操作、community/dmの変更、demand DBへのアクセスは行っていない。

非公開の原本は `.local/signed-e3-20261018-001/`、実行ログ・後処理記録は `.local/signed-e3-*`。runtime.env、パスワード、Cookieは公開証拠へ含めない。result.json内のapproval.assets_executed=falseは事前検証時点の状態で、復元全体では承認済みの資産を実行している。

## 公開判定と残る条件

「独立した承認情報の必須検証を通して、正常な模擬セットからWordPressを復元し機能確認できた」と説明できる。研究・開発版としての実証が進んだが、本番向けの侵害耐性・無感染復旧を認定しない。

同じWSLホスト・同じ担当者であり、元ホスト侵害や担当者不在への独立性は未証明。保存元主体による固定版削除・保持短縮・他ホスト制御、汚染世代の選定、検疫と再公開判定、別端末でのUSB復旧と鍵更新・失効運用、初心者の理解度試験は未完了である。
