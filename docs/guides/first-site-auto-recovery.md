# 隔離復元結果の自動登録（専用環境）

`first-site-daily-recovery-worker.py` が、承認済み日次セットの隔離復元と結果登録をつなぎます。復元と登録を別の状態として永続化し、登録失敗のためにS3取得・DB復元を繰り返さない構成です。生成データの専用環境向けで、実サイトの定期配置や管理画面は含みません。

## 実行する

WSLのリポジトリルートで実行します。`--state` は二資産用の専用日次台帳、`--trust` は独立保管した対象セットの信頼情報です。同一の復元要求には必ず同じ `--request-id` を使います。

```bash
python3 tools/first-site-daily-recovery-worker.py \
  --state "/二資産の日次台帳" run \
  --request-id "recovery-20261020-01" \
  --day "2026-10-20" \
  --trust "/独立保管先/対象セット"
```

日次の承認済み文書・公開鍵・設定のピンを復元処理へ渡し、復元側が独立信頼情報と照合してからS3へアクセスします。出力先は台帳内の `recovery-attempts/要求ID` で、新規作成のみです。要求の開始をSQLiteへ保存してから、固定版取得・署名検証・隔離復元・結果登録を実行します。署名鍵や保存側の認証情報は不要です。

成功・失敗の最終レポートが残った場合、そのSHA-256を固定して登録します。登録側は既存の証拠照合を省略しません。最終レポートは復元処理の正常終了時だけでなく、例外時にも保存されます。ただし、その証拠が不完全・期限切れ・署名不正などで登録できない場合は、復元結果とは別に登録待ちを表示します。

## 状態と再試行

日次の `status` に `recovery_attempt` が加わります。

|状況|要求の状態|総合表示|
|---|---|---|
|復元中|state=running|recovery_running|
|復元成功、登録完了|outcome=succeeded / registration=recorded|restore_verified|
|復元成功または失敗、登録未完了|registration=pending|registration_pending|
|最終失敗レポート登録済み|outcome=failed / registration=recorded|restore_failed|
|途中停止で最終レポートなし|state=interrupted / outcome=unknown|recovery_interrupted|

期限切れ・証拠不整合はこれらより優先して表示します。過去の成功観測は消しません。

登録だけ再試行するには次を使います。

```bash
python3 tools/first-site-daily-recovery-worker.py \
  --state "/二資産の日次台帳" retry-registration \
  --request-id "recovery-20261020-01"

python3 tools/first-site-daily.py --state "/二資産の日次台帳" status
```

- 同一要求のrun再実行でも復元処理は繰り返さず、必要な登録だけ再試行します。要求IDを別の日付や信頼情報へ使い回すことは拒否します。
- 登録がDBへ反映された直後に応答が失われても、再登録は同一レポートとして扱うため、観測は増えません。
- 最終レポート保存後にワーカーが停止した場合は、次の同一要求のrunまたはretry-registrationで証拠を照合して登録できます。
- 最終レポートがない途中停止は、次の排他取得時に中断として記録します。読取り専用statusだけではrunningを書き換えません。途中レポートを成功・完了レポートに作り直さず、再取得も開始しません。
- 実行中は台帳単位のOSロックで重複を拒否します。失敗・中断・未登録の要求が残る間は別要求も止めます。孤立した復元資源や登録拒否の原因を担当者が調べる必要があります。所有トークンのある専用資源は、後片付け手順で確認・削除して新規要求を許可できます。台帳削除による回避はしないでください。

run / retry-registration の終了コード0は「復元成功かつ登録完了」、それ以外の結果は2です。排他拒否や入力不正は例外による非0終了です。実際の状態はJSONと日次statusで確認します。

## 検証範囲

既存二資産台帳を別の専用フォルダへ複製し、実S3固定版から新しい隔離WordPressへ復元して自動登録を確認します。登録応答喪失、失敗レポート、最終レポート前のプロセス終了は明示的な障害注入です。環境障害や実S3の故障が発生したという意味ではありません。

復元結果の登録は同一ユーザーのローカル処理です。実行結果の独立署名・遠隔実行証明ではなく、本番再公開も承認しません。`restore_allowed=false` と独立検証の必須条件は維持します。元の三資産72時間観測、保存済みセット、共通部品、Backup for S3は変更しません。

[状態集約](first-site-daily-status.md) / [隔離復元](first-site-daily-restore.md)

途中停止後の明示的な確認・後片付け・新規要求への移行は、[隔離復元の後片付け手順](first-site-recovery-cleanup.md)を参照してください。生成データ専用CLIで実装・検証済みです。
