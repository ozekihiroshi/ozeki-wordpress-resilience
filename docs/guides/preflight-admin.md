# 導入前検査の管理画面（読取り専用・試作）

WordPress管理者は「Ozeki WordPress Resilience → 導入前検査」で、SSH棚卸しの取得結果、検査判定、未確認項目、最終検査時刻を確認します。5分以上経過すると情報が古いことを表示します。取得不可・応答不正・ホスト内検査失敗を区別し、古い失敗記録でも失敗表示を残します。本番導入可能やマルウェア不在を示す画面ではありません。

## 外部検査からの受渡し

[SSH棚卸し手順](host-inventory-ssh.md)の `inspect` に `--admin-report` を追加すると、サイトとプロファイルのハッシュ、検査時刻を持つ表示用JSONを標準出力へ出します。終了コード2は「確認が必要」を含むため、終了コードだけで記録を捨てないでください。SSH失敗も今回の失敗記録として受け渡します。設定ファイル自体が壊れているなど、表示用形式を作れなかった場合は、正常な検査結果として扱わず運用担当が原因を確認してください。

管理者が出力を確認し、Web公開領域外の固定ファイルへ一時ファイル＋renameで配置します。WordPress実行ユーザーには読取りのみを与え、ファイルと親ディレクトリーの書込みを許可しません。定期取得とローカル受渡しは [定期更新手順](preflight-relay.md) を参照してください。別ホストへのファイル配送は未実装です。

`wp-config.php`へ管理者が以下を設定します。画面から変更できません。

```php
define('OWR_PREFLIGHT_REPORT', '/var/lib/owr-public/preflight.json');
define('OWR_PREFLIGHT_SITE_ID', 'example-site');
define('OWR_PREFLIGHT_CONFIG_SHA256', 'プロファイルに対応する64桁のハッシュ');
```

設定を変更した場合はハッシュも更新し、棚卸しを取り直します。別サイト・別設定版・未来時刻・不正な形式・64KiB超過は表示を拒否します。未取得は未取得のままです。WordPressはSSH鍵やDB資格情報を必要としません。

## 表示の読み方

- 「棚卸し応答の検査済み」：応答の形式と対応関係を確認しました。未確認項目は別途対応が必要です。
- 「取得失敗・取得不可」：今回のSSH取得ができていません。接続・ホスト鍵・権限を調べます。
- 「情報が古くなっています」：最終検査から5分以上です。現在の状態は未確認です。画面を開いても再取得しません。
- 原因未確定：環境障害とも製品不具合ともまだ判断していません。

項目コードは調査用に併記します。任意の外部メッセージやホストのパス、DB資格情報を表示しません。管理者権限（manage_options）が必要で、GETのみを受け付けます。通知、再実行、削除、署名操作はありません。

## 今回の検証範囲

専用WordPress/MariaDBを有効化し、生成した報告を用いて実際のPHP管理画面描画、権限、POST拒否、状態保持を検証します。追加の専用Chromium試験で、通常・取得失敗・古い成功・古い失敗・未取得・不正記録の6場面、管理者／編集者／未ログイン、POST405、モバイル幅、読取り専用性を確認しました。古さは試験用の時刻を6分前に設定して検証しています。本番配置は今回の合格範囲に含みません。定期更新の検証範囲は定期更新手順を参照してください。既存72時間観測とは別環境です。
