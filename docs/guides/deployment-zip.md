# 設定生成・systemd配置のZIP候補

0.1.0-dev.1の試作版。WordPress用ZIPと外部処理の開発キットは別配布です。プラグイン更新は外部ホストのサービスや設定を変更しません。

## 今回の範囲

- 読取り専用の導入計画と、新しいディレクトリへの設定案生成。
- 生成パスを既存systemdサービスへ対応付ける専用環境の配置手順。
- 3VMでの周期実行・停止・再開・OS再起動・管理画面回復の証拠。

[生成設定](external-deployment-plan.md)、[配置](generated-deployment-lab.md)、[systemd検証](generated-systemd-lab.md)を参照してください。

## 導入と更新

WordPressにはプラグインZIPのみを導入します。[既存のZIP手順](preflight-zip.md)と同じく、更新前後で設定・Cron・要求・外部報告・警報台帳を比較します。同じ開発版番号での置換試験であり、バージョン更新通知の試験ではありません。

開発キットは新しいコード用ディレクトリへ展開します。設定・鍵・状態・履歴はコードの外に保持します。生成先に既存ディレクトリを指定した場合は拒否されます。新しい案と既存設定の差分を確認し、サービスの設定パス・ユーザー・書込み範囲を対応付けてください。自動適用・自動マイグレーションはありません。

## 試験と制限

新しい専用環境・生成データで、固定したZIPのPlugin_Upgrader導入・置換、無効化・再有効化、ファイル一致と設定・履歴保持を検証します。キットはZIPから展開したコードでplan/generateと既存設定上書き拒否を確認します。実SSH/systemdの検証は直前の3VM証拠を参照し、今回のZIP検証を再起動の再試験とは数えません。

原因未確定のWebDriverセッション作成タイムアウトは外部試験基盤の未解決事項です。プラグイン不具合やメモリ不足とは断定しません。ready確認と診断ログ保存を追加しましたが、その後の成功だけでは以前の根本原因は確定しません。専用SSHサービスの/run/sshd再作成不足は原因特定・修正・再起動再検証済みです。

72時間観測・正式公開・本番導入の判定とは分離します。既存の観測空白はそのまま保持します。
