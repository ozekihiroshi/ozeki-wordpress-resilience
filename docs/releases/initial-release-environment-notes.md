# 検証環境・試験基盤のメモ

2026-10-19。製品不具合一覧やプラグインの合否記録とは分けて管理する。元ログ・失敗イベント・原本ハッシュは保持する。

|事象|分かっていること|分類・対応|製品判定への影響|
|---|---|---|---|
|WSLのDNS障害|Windowsでは名前解決でき、WSLからのSSH接続確認が失敗した|環境問題。試験プロセス限定のDNS補助で回避済み。全体設定は変更していない|プラグイン不具合として数えない|
|初期writer待機のdrain_timeout|専用fixtureで一度発生。原因未確定。その後は待機制限を変えず、ローカル51項目と実S3保存34・復元42項目が合格|環境・試験基盤の調査メモとして暫定分類。常時調査は後回し。環境依存と断定はしない|この事象だけを製品の未達・公開阻害条件にしない|

再発して試験を進められない場合は、環境負荷・writerの処理時間・試験ハーネスを調べ、環境修正または根拠のある試験設定修正を行う。失敗時診断を追加済み。プラグインや提供対象の外部処理の欠陥を示す再現結果が得られた場合に、対象・期待動作・再現手順を添えて製品課題へ移す。

環境理由で試験が中断した場合は、その試行を製品合格にも製品不合格にも換算しない。「検証未完了／実行阻害」として記録する。失われた観測時間を成功として補完せず、必要な試験証拠は再取得する。環境問題を製品課題から外すことと、試験不足を隠すことは別である。

初日の二つの失敗は送信開始前と確認できたため、対象run・ログハッシュ・ソースハッシュをoperator-review.jsonに保存し、明示的に再試験した。結果不明のPUTを一般的に自動再送する運用ではない。このレビュー補助は専用試験ツールの機能であり、WordPressプラグインの機能追加・合格件数として扱わない。
