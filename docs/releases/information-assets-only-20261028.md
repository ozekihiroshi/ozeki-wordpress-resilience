# 情報資産を中心とした復旧への修正

追記：この記録で残件とした接頭辞の移行は、[rc.4候補](wordpress-org-033-rc4.md)で対応・確認済みです。以下は当時の検証記録です。

2026-10-28。WordPress.orgの0.3.3 rc.3に対する追加審査と、管理者の設計方針に基づく修正。未提出です。提出済みrc.3のZIP・タグは変更しません。

## 製品の境界

WordPress本体は新規導入、テーマ・プラグインは信頼できる配布元から管理者が導入します。S3から復旧するのは情報資産と対応する関係情報です。

- SiteSnapshotの旧software.zip展開・テーマ／プラグイン配置と、active_pluginsの上書きを削除。
- 旧資産のsoftware.zip・themes/・plugins/は復旧時に取得しない。元のS3オブジェクトは削除・変更しない。
- 必要なプラグインの事前有効化と、記録がある場合のバージョンを確認。ソフトウェアの導入・自動有効化は行わない。
- 復旧先のテーマ選択を維持し、別テーマ用の設定、旧custom_css・wp_global_styles、未対応の投稿種別、不明な項目は自動適用しない。
- 復旧ファイルは対応するアップロード資料だけに限定し、wp_upload_dir()が返す保存先を使用。独自の保存先URLにも画像参照を合わせる。Markdown原本は変更しない。

## 保存と互換性

実装前に影響を報告済み。新しい初期保存では実行コードの取得・software.zip作成を行わず、software_inventoryにテーマ／プラグインの名称と版を記録します。recovery_modeとsource_upload_urlも記録します。情報資産の分離形式、正式履歴、既存の参照形式は維持します。

修正版は既存Baseline・Checkpointと正式履歴を読めます。既存資産を書き換える移行はありません。旧Checkpointのコピー・保持処理は従来の資源を保全しますが、復旧処理ではコードを使用しません。復旧先は最新版を使用します。

## 配布パッケージ

実行に必要なファイル、利用手順、ライセンスのみを同梱します。明示した利用文書だけを収録し、検討資料・検証記録・旧候補説明はGitHubに残します。vendor内のAGENTS.md、CLAUDE.md、開発資料、bin、Python/BAT、コード検査設定なども除外します。依存ライブラリのライセンスとNOTICEは保持します。
