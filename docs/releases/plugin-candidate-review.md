# GitHub公開候補：0.1.0-dev.1

候補名：Ozeki WordPress Resilience 0.1.0-dev.1 — 通知管理画面と外部復旧ツールの開発版

## 公開説明案

WordPressの通知設定、独立watchdogを含む外部状態表示、テスト送信要求を扱う管理画面の開発候補です。インストール用ZIPと、外部処理・専用試験・仕様を含む開発キットを分けました。

プラグインを有効化するだけではバックアップ・署名・復元・監視・通知配送は始まりません。取得・保管・署名・復元は外部CLIでの専用検証段階です。汎用サイトへ導入してサイト保護が完成する製品版ではありません。

## 今回の確認

- 配布ZIPを新しい隔離WordPressへ標準Plugin_Upgrader APIで導入し、有効化・管理画面・設定保存・権限拒否・状態表示・テスト要求・無効化／再有効化を確認。設定と外部要求ファイルを保持。
- 結果は[ZIP導入試験](../../evidence-public/plugin-package-install.json)。182チェックは繰返しのログイン確認等を含む管理画面と外部境界の検査で、182個の独立した製品機能を意味しない。外部配送は模擬、実通知0、試験コンテナ削除済み。
- ブラウザーのファイル選択・アップロード操作自体は未自動化。ZIPインストールはWordPress標準API、画面は実HTTP/Chromiumで検証。
- 配布ビルドの対象制限、再現性、既存出力保護、版不一致・秘密鍵形式・symlinkの拒否を7件で検証。
- 最終配布物のファイル一覧・SHA-256は同梱manifest.json。展開した開発キットの検証結果は配布フォルダのcandidate-validation.jsonを参照。

## 差分の確認範囲

今回の変更は配布対象の明示、ビルダーとテスト、ZIP導入試験入口、プラグインの版と機能範囲案内、導入・公開説明。設定保存や配送の既存契約は変更しない。通知キーや実データをZIPへ取り込む処理はない。過去の大量の未コミット成果を破棄・履歴改変しない。今回のチェックを全コードのセキュリティ監査とは呼ばない。

## 未達と別評価

- 汎用バックアップ機能のプラグイン統合、任意の更新経路制御、本番外部配置の自動化、鍵失効・代替担当・再公開承認は未達。
- Pushover/メール以外の通知方式は未実装。SMTPの今回の実接続確認は行っていない。
- 3日次枠・72時間の外部構成観測は並行実施中。これを理由に開発候補の導入検証や配布準備を止めない。観測合格や本番完成を主張しない。
- 環境・試験基盤のメモは製品課題から分離。[分類](initial-release-environment-notes.md)を参照。
- Ozeki Database Backup for S3とは独立導入。共通PHP DB部品はpackages/backup-coreで管理し、固定版と契約試験で扱う。今回の管理画面ZIPがDB取得を実装済みとはしない。
