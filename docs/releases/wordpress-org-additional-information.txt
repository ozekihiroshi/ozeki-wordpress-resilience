Concept and scope: this reconstructs supported state from a trusted Baseline, saved originals and confirmed history. It is not a whole-server image or a general database-and-files restore. Checkpoints assemble saved resources and do not discover untracked live changes. Only confirmed history is recoverable after source loss. The reorganized readme separates workflow, supported scope, exclusions and administrator prerequisites; no functionality or broader guarantee is added.

All runtime libraries are included. No external Python worker, SSH helper or runtime kit is required. AWS credentials use the standard SDK provider chain. Service terms, privacy, data transfers and setup requirements are disclosed in readme.txt and the included guides. Native-only Baseline/recovery does not require Markdown Documents; it is required when Markdown content exists. Optional integrations and tested versions are documented.

Important review detail concerning Guideline 8: at an administrator's explicit request, site recovery can restore selected theme/plugin files from that administrator's own captured S3 backup, alongside content. This is a backup/recovery workflow, not a developer-hosted plugin update channel. We disclose this behavior for your assessment; we do not claim a blanket exception from Guideline 8. Recovery reproduces saved publication status, including publish, and does not certify restored code/content as malware-free.
