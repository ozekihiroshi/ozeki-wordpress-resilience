# v0.1.0-alpha.4 — 再構築機能の初版（試作版）

対象はWordPress保守技術者です。まず専用環境の実画面で、会社案内・サービス・連絡先を編集して動きを確認します。GitHubの試作版公開であり、本番導入やWordPress.org公開ではありません。

## 最初に見る画面

専用環境で「固定ページ → company / services / contact → 編集」を開くと「S3先行保存 — ページ編集」が表示されます。本文・タイトル・スラッグを編集し「S3へ保存して反映」を押します。完了時は世代を表示し、未完了は「同じ保存を再開」、競合は最新状態の再読込みで扱います。WordPressは表示用の反映先であり、復旧元は不変の世代と保存要求由来Qです。

## 配布物の違い

- `ozeki-wordpress-resilience-0.1.0-alpha.4.zip`：WordPressへアップロードして有効化する管理・状態表示プラグイン。これだけでは対象ページ登録やS3先行保存は始まりません。
- `owr-development-kit-0.1.0-alpha.4.zip`：編集/API・S3・署名付き再構築・専用試験・文書の外部キット。WordPressのアップロード欄には入れず、別に展開します。
- `manifest.json`、`SHA256SUMS`：配布物の同一性確認用です。

## クラウド資格情報なしで触る

専用Linux/WSLにDocker、Python3、PHP8.1以上（mysqli/GD）、Composerを用意し、キットを展開して `composer install --no-dev` を実行します。`requirements-dev.txt` の依存、`lab/m1/images.env` の固定WordPress/MariaDBイメージ、対応するChrome/ChromeDriverを含むローカルSeleniumイメージが必要です。[英語手順](alpha4-preview.md#first-screen-without-cloud-credentials)のコマンドを実行します。新旧プラグインZIPと未使用の専用出力先を指定してください。

試験後にローカル画面を残す指定が `--keep-local-demo --demo-port 18714` です。専用出力先の非公開 `demo.json` にあるURLを開くと、試験管理者としてログインします。このURLは公開しないでください。固定ページ一覧から上記3ページを編集できます。

この画面の保存先は永続化するS3模擬ストレージであり、実AWSではありません。[実験用S3での一貫検証](../../evidence-public/rbr-request-q-live.json)は別の証拠です。模擬画面からメール・本番通信・署名は行いません。公開ポートはループバック `127.0.0.1:18714` のみです。すでに試験で変更された内容もすべて生成データです。

停止は `demo.json` の正確なweb/db名を指定して `docker stop`、再開はdb→webの順で `docker start` します。状態を残す間は出力先・コンテナを保持してください。不要と判断してから、その2コンテナと記録された専用ネットワークだけを削除します。

## 実S3と署名付き再構築

実S3へ接続する場合は、[編集仕様](../spec/rbr-wordpress-editor.md)と[Q仕様](../spec/rbr-request-q-jp.md)に沿った明示的なページ登録・固定版/保持付き保存・限定権限の設定が必要です。汎用の本番導入ウィザードは未実装です。常設の別EC2を必須にはしていません。

編集後の適用済み応答（expected_refを含む）と固定R/E/Cのプロファイルを既存のキット生成入口へ渡します。Qを手書きしたり復元結果から作ったりしません。キット生成は独立承認待ちで止まり、別の署名担当の承認と既存の鍵・最新台帳・失効・期限検査を通過したものだけ隔離再構築します。自動公開はありません。

## 初版の範囲と制限

登録済み3固定ページ、段落の平文、タイトル、スラッグ、既存登録画像とページ関係が対象です。通常投稿・Gutenberg・Markdown・新規画像登録・旧台帳の自動移行・未完了操作の破棄・自動署名・承認延長は未対応です。他の更新経路や独自プラグインを含む本番保護は保証しません。Qは意図の検査であり、無侵害の証明や署名承認の代用ではありません。

更新時は設定、完了/未完了台帳、Q、S3参照、署名・信頼履歴を保持します。Q用文脈がない古い登録状態は初期化せず拒否します。旧コードと状態を保持し、移行を別途判断してください。管理プラグインの更新だけでは外部キットの移行は行われません。

実S3試験は3世代・ブラウザ21項目・独立試験署名・元作成元を隠した2環境のQ一致、回帰試験75件を確認済みです。同一ホスト上の別署名アカウントと既存OCIキャッシュを使っており、物理分離やコールドキャッシュの実証ではありません。過去の短縮観測は68時間28分24秒・観測空白2件のままで、今回の新経路の連続観測実績とは扱いません。

最終ZIPの導入・更新結果は、ZIP固定後にReleaseの別添付として公開します。補助試験のJSON正規化・シェル引用・過去のブラウザ起動問題は製品の課題と区別します。

環境記録：初回デモ準備ではWordPress起動前にDocker自動アドレス枠が不足しました。既存ネットワークと経路との重複を検査し、専用の未使用/28を選ぶ方法へ修正しました。既存ネットワークは削除・変更していません。

Docker内部ネットワークは外部ポートを公開しません。専用Python中継だけを127.0.0.1で待受け、単一の試験WordPressへ渡します。デモ停止時は非公開demo.jsonのproxy_pidも停止してください。必要ならtools/rbr-local-demo-proxy.pyに現在の専用コンテナIPv4とポート18714を指定して再開します。全インターフェースには公開しません。
