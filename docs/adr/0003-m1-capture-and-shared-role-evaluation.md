# ADR 0003：M1実証の収集索引と権限分離の評価

2026年10月18日。

既存バックアップ製品のPHP DBダンパーを固定コミットから再利用し、ファイルは新製品の明示的な収集アダプターで取得する。既存RecoveryCollector/Publisherの出力を装わず、format=owr-capture-manifestの独自収集索引を用いる。上位RAMのrecovery_manifest資産は、このM1ではこの収集索引を指す。従来案のodbfs3-recovery-set参照に限定する方針を変更する。

理由：既存内部Pipelineのmediaは個別オブジェクト形式、今回の収集は検査済みtar形式であり、既存形式へ無理に詰めると検証方法や実測履歴を偽ることになる。M1の復旧条件に必要なのは、組合せを確定したDB・全ファイル・構成・実行環境と実取得証拠である。既存製品の形式・コードは変更しない。既存manifest連携は後続の別アダプターとして追加できる。

runtime資産にはWordPress/PHP、MariaDB、nginxの3つの固定イメージをまとめて含める。Bootstrapには復旧プログラム、独立環境定義を生成する処理、検査コード、基準データ、イメージIDを含める。実験の管理者パスワードとDB資格情報は復旧時に新規生成し、構成へ長期AWSキーを埋め込まない。

利用者は「今回は同一ロールで検証し、権限分離は未達として評価する」を選択した。別ホストdmで固定版を取得し、独立Dockerボリュームで復元する機能試験を進める。保存側と復旧側の両方がExampleSharedRoleであるため、IAM境界による独立性や侵害耐性は未達。単にPhase 5へ到達したことを、サイバー攻撃に対する完全な実証成功とは表現しない。
