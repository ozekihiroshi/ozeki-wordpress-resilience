# ADR 0002：上位RAMと未検証状態を保持するBootstrap

決定日：2026年10月18日。Phase 2で採用。

既存プラグインの厳密なRecoveryManifestを拡張せず、サイト全体のRAMからバイト単位で参照する。既存製品の収集機能を変更しない。内部APIを呼ぶ収集アダプターの採用確定はPhase 3の契約試験時とする。

ローカル、固定版S3、未確定という3種類の保存先を区別する。S3 Version IDとハッシュのない資産を確定した資産として記録しない。RAM原文を上位Recovery Setのハッシュで束縛し、同じIDの再発行を拒否する。未確定資産を埋める場合も新しいIDを使う。

署名や独立アンカーの運用がない段階で真正性を主張しない。Phase 2ではauthenticity=unverifiedを固定する。外部から渡された期待ハッシュとの一致と、信頼の確立は別の結果として扱う。署名鍵管理・失効設計のない中途半端な署名を導入するより、未検証を明確に表現する方針を採用した。

発見：Ubuntuのjsonschema 4.10.3では追加の日時検証依存がないとformat=date-timeの検査が有効にならなかった。負の試験で検出し、Python標準ライブラリによる形式・実在日時・タイムゾーン検査を追加した。

制約：pendingを含むセットは復旧準備完了ではない。ローカル排他的生成は改変耐性の代替にならない。Bootstrap配布物の独立保管と信頼、S3取得、内部manifest照合、全資産の版固定、実復旧は後続フェーズで検証する。
