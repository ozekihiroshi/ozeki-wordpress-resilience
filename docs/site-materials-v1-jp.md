# サイト素材からの再構築（開発中）

ResilienceはBackup for S3を必要としません。投稿内容をWordPressへ反映する前にS3へ保存し、その原本から再構築します。DBダンプは再構築の入力にしません。Gitは例えであり、互換実装ではありません。

新経路は複数の通常投稿・固定ページ・PNG/JPEG、親子ページ、本文内の段落・見出し・リンク・画像の順序を扱います。全素材の一覧で世代を確定し、一覧から外した素材は削除を表します。参照が残る削除は拒否します。素材は個別gzip圧縮し、同じ内容は日単位の保持枠内で再利用し、新しい保持枠では別の保持付きコピーを作ります。差分チェーンや親世代の取得は復旧に不要です。

担当する書込みホストは1台に限定します。ロック・要求ハッシュ・親世代照合で重複や古い操作を拒否します。別ホストからの同時書込みはまだ非対応です。結果不明のPUTは既存台帳で止め、推測して再送しません。保持不足の原本は新しい保持付きコピーにし、旧版を上書きしません。

新経路の標準は自動整合性検査です。人による署名とは区別します。署名必須を指定した場合、独立検証器がなければ停止します。旧署名経路の承認条件は変更しません。

専用WordPressでは新規再構築と親世代が一致する連続反映を扱い、同じ要求の再実行は重複しません。DB反映はInnoDBトランザクションです。失敗時の新規画像ファイルは残る場合があります。生成物はすべて下書きで、自動公開しません。

現時点の新経路はCLI・開発者向けです。既存の3ページ編集画面を一般投稿用へ変更したわけではなく、通常のGutenberg・クラシック編集・画像登録は未接続です。Markdownは通常文と見出しの限定範囲、その他は明示的に拒否します。フォーム・独自ブロック・ユーザー・認証情報・PDF等は対象外です。

実験のEC2は既存S3試験権限の署名に使用します。常設の別EC2を製品の必須条件にするものではありません。実行環境は固定したローカルDockerイメージを使うため、実行環境までS3だけから取得する新しい実証とは区別します。

旧バックアップ系は移植候補と重複を調べてから分離します。過去の証拠を削除せず、未移植のものを移植済みとは扱いません。

## 専用編集画面への接続

新しい専用WordPressへ `SiteMaterialsEditor::boot($bridgeDirectory)` を明示設定します。試験ランナーが設定し、既存サイトや既存ZIPを自動移行しません。CLIと画面は同じ `SiteMaterialsProjection.php` を使います。

1. 投稿・固定ページの編集、画像新規登録の入口から「S3先行編集」へ移動します。素材選択、投稿・固定ページ追加、PNG/JPEG登録ができます。本文は段落・見出し・素材IDへのリンクと画像参照に限定します。
2. 保存要求を固定し、単一ワーカーがS3固定版保存・取得を確認した後にだけWordPressへ反映します。画像選択時点では添付ファイルを作成しません。
3. 失敗時は従前の内容を保持します。再読込しても保留要求が残り、「同じ要求を再開」で続行します。異なる保留要求・古い世代の操作は拒否します。保存結果不明の場合は自動再送しません。
4. S3確定後の停止では台帳を照合し、同じ世代から再開します。反映失敗はDBをロールバックし、自動反映リトライを停止します。未参照画像ファイルが残る場合があります。

管理者権限とREST nonceが必要です。この明示登録した試験環境では通常REST・挿入削除・画像アップロードによる迂回を止めます。直接SQLや任意の第三者コードは制御対象外です。WordPress内部のナビゲーションは素材数の照合対象外とし、削除しません。

今回は下書きへの反映です。本番の公開状態を維持する更新、通常Gutenberg／クラシック編集、汎用Markdown、独自フィールド、一括取込、既存サイト導入は未対応です。旧3ページ署名経路の承認条件は変更せず、新しい素材経路は別記のintegrity方針を使います。
