# ACF無料版の適用契約 — 開発中の限定検証

2026-11-11。この照合処理自体は製品の保存処理・復旧処理には組み込まない。提出済みrc.10は変更しない。

## 照合するまとまり

| 対象 | 比較内容 |
|---|---|
| フィールドグループ | key、タイトル、適用先条件、active、所属フィールド |
| フィールド | key、name、label、type、および現行の適用対象となる必須条件・初期値・選択肢・複数選択・空欄許可・返却形式・入力範囲・表示設定・順序等。全項目名は `AcfApplicationContract::FIELD` |
| 記事・固定ページ | 所有先の種類、保存値、フィールドキー参照。未設定は空のメタ行配列、保存された空文字は1行の空文字として区別 |
| 欠落・追加 | 必須の比較項目を削除したら不合格。想定外のグループ・フィールドも不合格 |

期待値は検証済み原本から組み立てた適用前状態から取得する。製品のprojectやcaptureを使って期待値を生成しない。復旧先はACF APIとWordPressメタデータAPIで読む。定義はAPIで補われる標準値も含むため、同じACF版を前提とする。

これは正常な対応データを対象とする初版である。ローカル定義・未対応型・対応しない参照は入力エラーとし、黙って正常な欠落に変換しない。任意の原本に対する未適用判定を製品同等に実装したものではない。対象外の設定、ACF Pro、任意の拡張型は今回の合格範囲に含めない。削除済み定義への残存値、適用先条件の対象外ケース、未知のメタデータ全件の検査もこの初版では完了していない。

## 実行と結果

専用隔離サイトでのみ実行する。入力はWP-Members照合と共通のprivate JSON構造（raw以下にtablesとacf）。秘密を含む入力はコミットしない。

```sh
php tools/testing/acf-contract-check.php /isolated/wp-load.php /private/expected.json
```

- communityの既存隔離fifthサイト、WordPress 7.1.3 / PHP 8.3.36 / ACF free 6.8.10。
- 適用前の既存原本と、復旧先の値・定義・参照が一致。
- 267箇所の末端項目を比較用メモリコピーから1つずつ削除し、267件すべてを検出。
- 隔離DBのトランザクション内で、text定義の必須条件・placeholder・maxlengthを変更。変更前の定義へ戻してから新定義を製品のproject/installで適用し、定義全体が一致。
- 同様にフィールド定義の削除を適用し、余分な定義が残らないことを確認。
- 変更・削除それぞれロールバック後、posts/postmeta/options全行のハッシュが一致。最後の読み戻し照合も再度合格。
- この変更・削除試験はアダプター適用試験であり、実S3で保存→復旧→再保存→再復旧したという意味ではない。

## 次に解消すべき確認点

定義変更が保存される起点について問題候補を発見した。`AcfHistory::boot()`は記事保存とメタ更新等を監視し、`mark()`はpost/pageだけを対象にする。定義の投稿種別acf-field/管理グループ自体は対象にならず、定義専用の更新・削除監視は当該ソースにない。

保護有効の設定をメモリ上のフィルターで与えた診断では、同じmarkメソッドに対してフィールド定義はキュー0、公開記事はキュー1。診断用オブジェクトはbootせず、shutdown・S3書き込みを実行していない。定義のみを変更したHTTP操作から正式履歴までの実証は未実施。

したがって「定義だけ編集し、記事を保存し直さない場合」も新しい定義が正式履歴へ確定するかを、次の限定的な実S3確認対象とする。新しいBaselineや後続の記事保存で取得できることと、変更時点の履歴へ残ることを区別する。今回の一致結果でこの課題を合格扱いしない。

上記は初回調査時点の状態。その後、実S3で定義単独の変更・削除が記録されないことを確認した。ただし現行公開文書は新Baseline作成を要求しており、既存保証への違反という分類は訂正した。

ユーザー承認後、この開発ブランチには独立した定義履歴を追加した。実S3で定義の変更・削除・グループのゴミ箱移動と復帰・記事ゼロ・再保存と再復旧・Checkpointを確認した。独立定義履歴が存在する場合、記事に同梱された古い定義では上書きしない。旧原本は新版で読め、新履歴と新しい形式識別子の復旧点は旧版で拒否される。

詳細記録は作業領域の `release-readiness/acf-definition-fix-20261111/REPORT-ja.txt`。main取り込み・push・新ZIP作成はまだ行っていない。開発用照合コードは正常な対応データを対象とする暫定段階で、全公開条件を満たす検証機構とは扱わない。
