# Isolated media-access regression

These fixtures are development checks, not a plugin feature or a deployment procedure. They use synthetic content, fake S3 transport, three dedicated WordPress containers, an internal-only Docker network, no published ports, disabled mail/Cron/external HTTP, and unique database/volume names. Never point them at production.

`run.py` expects a writable evidence directory containing `fixture.php`, the current package's `src/`, `wp.phar`, a preserved installable `candidate.zip`, the official `wp-members.zip`, and the lab SDK transport (`../coexistence/transport.php` in this repository). The ZIP installs runtime dependencies; current source is overlaid only in these containers. No release ZIP is generated or changed. Run with the existing dm rootless Docker environment. Resources are listed in `resources.json`; remove only those exact resources after inspection, keeping the evidence directory.

Run `python3 assert-results.py results/summary.json` after `run.py`. The independent assertions require the fixed fixture byte hash, anonymous/member page visibility, actual HTTP status, durable held bytes, absence of pending history, the condition-only history event, and the resaved edit after the second recovery. Assertions reject the pre-fix daily-boundary results.

Cases:

- A: image added to an article after the initial capture.
- B: only an existing attachment's restriction changes after capture.
- C: a newly restricted image is added to an article after capture.
- D: only the parent page's WP-Members restriction changes.

`extended.py` reuses the newly created resources for explicit restriction removal and directory-only recheck. It then uses **separate empty DB prefixes** for genuine legacy captures and histories copied from the earlier daily-boundary trial. Adjust its `old` evidence directory to the preserved legacy fixture; do not modify that directory. The old objects' hashes must remain identical. Legacy files are held through use, resave into a new writer namespace and a second restore. The fixture refuses unexpected hosts. Every fixture operation returning `operation_failed` now stops the runner immediately.

For format compatibility, `../media-access-format.php` accepts a package path, `../fixtures/media-access-legacy.json` and an output JSON path. That fixture was generated by main `054d5a2`'s actual writer. `../reference-legacy-reader.php` accepts the **actual frozen old package** and the output JSON, proving that the old reader accepts old data and rejects both new originals and snapshots. The new-reader check is in CI; the actual-old-reader check was also executed in the isolated trial.
