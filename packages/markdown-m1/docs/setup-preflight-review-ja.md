# セットアップ前の条件判定 — 現状整理

[English](setup-preflight-review.md) · [導入ガイド](user-guide-ja.md)

2026年10月28日。対象ソース：2cf014c（0.3.1系）。コードと既存文書の読取りによる整理。機能追加・実行試験は行っていません。この文書は新機能の仕様確定や実装予定を意味しません。

## 現状

現在は設定保存、初期保存、通常保存、復旧などの各操作で条件を確認します。セットアップ前に全条件を一覧で示し、合格後に保護開始へ案内する画面はありません。設定を保存できることと、実際に保存・復旧できることは別の確認です。

| 確認する項目 | 現行実装で確認していること・時点 | 事前判定として追加が必要なこと |
|---|---|---|
| WordPress・PHPの版 | プラグインヘッダーで最低版6.4／8.1を宣言。復旧時は保存時のWordPress系列と修正版を比較 | 現在値と必要値の一覧表示。WordPress側の最低版判定と、製品独自の準備完了判定を区別 |
| PHP拡張・容量 | ZipArchiveを保存・復旧で使用。ZIPアップロードはWordPress/PHP側の処理 | ZipArchive等の利用可否、アップロード・POST上限の事前表示。Webサーバ上限や処理時間・容量は確認できた範囲と担当者確認を分ける |
| DB | 保護処理のlockでposts/postmeta/optionsのInnoDBを確認。復旧時は復旧対象表、会員復旧は会員関係表も確認 | 保護開始前に必要表の方式を一覧確認。既存の検査を破壊的処理なしで共用する整理 |
| 書込み先 | 復旧時にWeb公開領域外の一時領域を作成し、書込み可否と配置先を確認 | 一時領域、uploads、対象テーマ等の準備状態を事前表示。実際の書込み試験は必要な場合だけ、試験ファイルを限定 |
| 保存先の入力 | 設定保存時にbucket/region/prefix/ownerの書式を確認。ownerは現行実装では空欄も許容 | 項目別の説明、所有者ID未入力の案内。書式の正しさと接続成功を分ける |
| WebのPHPからのAWS認証・権限 | 実際の一覧・保存・取得操作でSDKが認証し、失敗はエラー表示。owner指定時はAWS要求に含める | 同じWeb実行環境で役割別の準備確認。接続、一覧、保存、固定版読取りを分けて表示 |
| バージョニングと保存内容 | Store::putで保存結果のVersionIdを要求。初期保存では固定版を再取得して照合 | 設定前の確認と実保存後の確認を分ける。書込みを伴う確認は専用試験資源とし、削除禁止ポリシーでの残し方も決める |
| 削除ロック・保持 | ロック要求時の保存・保持延長・再読取りで確認。保持0はロック要求なし | 任意機能として判定し、使わない場合は対象外と表示。既存ロックを変更する事前試験はしない |
| 連携プラグイン | 初期保存でMarkdown文書の存在・有効化等を確認。フォーム・会員・TablePressは各復旧経路で依存条件を確認 | 利用中の連携機能と必要版の一覧。未対応プラグインの存在を全体の導入失敗にせず、そのデータの対象外を案内 |
| 未確定保存・復旧先 | 初期保存等で未確定操作を検出。復旧時は保護オフ、未確定本文なし、元と異なるURL、置換同意を確認 | 保存元／復旧先を先に選ぶ導線と、各役割の準備項目を表示 |
| 定期処理 | 設定値を正規化し、予定を登録・表示 | 実行機会・直近実行の案内。予定があるだけで確実に起動すると判定しない |
| 同じprefixを使う別サイト | ローカルDBのロックとS3への条件付き書込みはある。別サイトを網羅して検出する仕組みはない | 専用prefixの確認案内。所有サイト確認を自動化するなら別設計が必要 |

## 自動判定と管理者の判断を分ける

初期状態を信頼する判断、攻撃後に戻す変更の選択、保存する権限、データの扱い、公開とDNSの判断は、機械的な環境チェックの合格に含めません。利用者の確認項目として分けて表示する整理が必要です。

## 将来の画面を作る場合の整理

「環境確認 → 保存先設定 → 実際の保存・読取り確認 → 初期保存 → 保護開始」の順とし、各項目に「準備完了／要対応／未確認／今回使わない」を表示する案です。要対応では担当者と次の操作を示します。復旧先は読取り専用の確認経路とし、書込み・削除テストは行わない構成にします。

準備完了はその時点の条件についての結果です。設定や認証が変わった場合の再確認が必要になるため、確認日時と対象設定を持つ仕組みも追加対象です。既存の実行時検査は維持します。
