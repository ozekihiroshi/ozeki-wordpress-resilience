# Recovery attribute and setting rules

## Boundary

`RecoveryRules::project()` runs in complete-site restoration **after** loading the selected snapshot and replaying the selected confirmed history, **before** destination files or content are replaced. Initial snapshots and subsequent history therefore use the same final application rules. Capture, original storage, Checkpoint generation and S3 resources are unchanged. Projection operates on an in-memory copy; unknown captured information remains in the selected S3 resources. A subsequent Checkpoint is never built from this filtered destination projection.

The existing adapters declare their recognized metadata/settings. Known values with invalid types stop recovery before replacement. Unrecognized keys are withheld and reported by path/reason, without copying their values into the report. Result `application_report` records the rules version, omitted paths and count; the admin result displays them with the existing detailed JSON. A failed/latest attempt does not present an earlier successful omission report as current.

## Rules in this first implementation

| Area | Automatically applied | Preserved in originals but withheld |
|---|---|---|
| Core and Markdown | Body/source unchanged; core article identity/details through existing replay; known image/attachment, featured-image, page-template, menu, trash and recovery identity metadata; known core options | Unrecognized post/term/comment metadata. Markdown source hash is regenerated by the existing renderer, not imported. Core comment trash state is retained |
| CF7 | Form definition, locale/hash, recognized mail-template fields and messages; core `skip_mail`, `demo_mode`, `acceptance_as_validation`, `subscribers_only` directives | Unknown nested mail settings, other additional directives and extension metadata. Recovery does not replay mail |
| Flamingo | Submitted fields, subject/sender, submission status, consent/hash, spam timestamp; post state/channels via existing replay | Other metadata, including third-party analysis payloads; no attachment/address-book extension |
| WP-Members | Existing subscriber/identity checks, approval/restriction, recognized basic settings, core registration-field definitions and values, dialogs/terms | Unrecognized setting keys or field types; session/privilege metadata remains excluded. Only existing captured resources can be retained; this does not add capture of previously excluded credentials |
| TablePress | Table content/IDs, recognized visibility, headers, sorting/search/pagination controls and registry/version settings | Custom DataTables commands, custom CSS/module/extension and editor-notice settings. Custom CSS and modules are disabled in the destination projection |
| Theme/widget settings | Menu locations, custom logo and basic background/header text colours | Other theme-specific settings and all widget option payloads in this first rule set |

Definitions are in FormHistory, MemberHistory and TableHistory; common core metadata is in RecoveryRules. Structured submitted content is retained as data; this is not a content sanitizer or a proof that HTML/Markdown is harmless. CF7 form text and body content are not reparsed into a new security language. Supporting a plugin does not certify arbitrary extensions.

## Preparing software

Install WordPress, themes and required plugins from trusted distributors. Recovery does not install archived program files or change the destination theme and active-plugin selection. Theme settings are applied only for the selected theme. Saved custom CSS, global-style records and post types without a supported recovery rule are withheld. Use the recovery result to inspect withheld items; their source originals remain in S3.
