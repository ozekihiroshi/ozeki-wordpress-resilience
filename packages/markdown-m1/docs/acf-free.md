### Research branch: ACF free basic fields (unreleased)

The research adapter captures completed ACF saves on published or already-protected posts and pages. Values, complete field definitions and field-key references are separate JSON originals; unknown settings and raw metadata remain in the stored original. Confirmation uses the existing fixed-version readback/hash verification and pending-history queue. A WordPress field save is not confirmation in S3; queued failures remain pending for explicit history resumption (see the capture-failure boundary below). Body history and ACF field history are separate confirmed operations.

Automatic application is limited to database-defined groups with post/page post-type location rules and these field types: text, textarea, number, range, email, url, select, checkbox, radio, button_group, true_false, date_picker, date_time_picker, time_picker and color_picker. Recognized values, choices and field keys are reconstructed through complete-site recovery; unrecognized types/settings are retained in originals and listed as not applied. The destination must have the recorded free ACF version active. Baseline and later history share these rules; Checkpoints consume S3 assets/history only.

ACF PRO is not supported or planned. Media/post/user/taxonomy reference fields, nested fields, custom post types, options/user/term/comment fields, PHP/Local JSON definitions, and definition-only edits without a subsequent protected post/page field save are outside this first adapter's acceptance scope. Use a new trusted Baseline for standalone definition changes. No cross-version conversion or automatic sanitization guarantee is added. Existing published ZIPs do not include this research change.

## Verification and integration boundary

On 2026-10-28, ACF free 6.8.10 on isolated WordPress 7.1.3 passed standard Gutenberg edits of a test post and page, real S3 fixed-version original readback and confirmed history, and complete-site recovery through the dm administration screen. The source, S3 originals and destination matched for all 15 basic field types, field-key references and ACF get_field() results, as well as body/title/publication state. Not every type was edited in the browser; unchanged fixture values were also compared. The latest ACF records were 5 and 10; recovery used Baseline through 0 plus history through 10. Body, native details and ACF have separate records; intermediate ACF states can occur. One editor save does not mean one history record.

Values, definitions and references were three independent JSON originals. Unknown settings remained in originals. Recovery reported 151 unapplied items, including unsupported ACF settings/types and fixture WordPress widgets; this is not a count of lost supported values. The destination had the same software preinstalled (files written: 0); this was not a plugin-binary installation test. Recovery read S3, not the source database; the source server was not shut down.

Earlier isolated CLI tests with simulated S3 covered Baseline, independent Checkpoint plus tail, comparison failure and frozen-payload resumption. Those failure injections are not real AWS outages. The real S3 trial covered the successful path only. Test preparation's duplicate PHP include and browser meta-box layout/response delays were environment/harness issues.

This PR ports the tested research adapter onto public main without reverting its setup checks, translations or packaging. Offline contracts are rerun on that integration. The live S3/browser evidence belongs to the research build, not a newly deployed main build. Published ZIPs and the release version are unchanged. Release/merge decisions belong to the public-line maintainer.

ACF capture runs after the WordPress field save. A confirmed operation requires S3 readback verification and formal history; it is not a cross-system transaction or proof of malware absence. Queued failures require explicit history resumption. Capture failure before queue registration is shown by the existing save-failure mechanism and can require saving again; do not assume every failure leaves a resumable payload.
