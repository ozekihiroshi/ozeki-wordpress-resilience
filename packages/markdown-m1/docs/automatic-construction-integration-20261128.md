# 管理操作の自動記録・初回保存の境界・Flamingo登録の接続

2026-11-28。S3なしの隔離開発実装。本番への導入、既存原本・履歴の変更、ZIP作成、push、申請、メール返信は行わない。

## 実装

- `ConstructionCapture` は通常の管理HTTP操作とREST操作を処理前に捕捉する。試験側が操作ごとに記録関数を呼ぶ方式とは別である。
- `ConstructionOperations` は入力の事前保存と、通常登録後の結果確定を分ける。未確定操作は成功扱いしない。ローカルの専用optionだけを使い、S3の正式履歴へ確定したとは扱わない。
- `initialSave()` は既存のmanifest・ファイルを変更せず、別の接続情報に内容ハッシュと操作到達点を記録する。`afterInitialSave()` は同じ初回保存であることと、到達点までの記録が不変であることを確認して後続だけを選ぶ。
- `FlamingoReconstruction::recorded()` は、CF7からFlamingoに渡された入力と元の登録結果を使う。復旧先のフォームへの参照を接続し、Flamingoの通常の `add()` へ渡す。CF7のfeedback送信は呼ばない。
- 再構築先でも、この通常登録に実際に渡す入力を記録し、次の再構築へ使う。登録結果を加工して期待値に合わせない。

## 既存データへの影響と限界

`owr-observed-construction-experiment-1` と `owr-construction-anchor-experiment-1` は開発用の別形式。既存のS3保存形式・正式履歴・初回保存を書き換えず、公開済みのreaderへ新形式を混ぜない。製品の `Plugin::boot()` には接続していない。`OWR_CONSTRUCTION_ISOLATED === true` を明示した隔離環境だけで起動する。

過去の初回保存に、新方式の操作到達点は存在しない。後から現在の番号を付けて「その時点までの操作を含む」と見なすことはしない。今回確認する接続は、同時に到達点を記録して新規に取得する初回保存と、その後の操作である。**到達点のない既存初回保存だけから、新方式へ完全に接続できたという意味ではない。**

古い初回保存の素材を通常登録する処理と、その登録で得た参照対応を新しい操作列へ渡す作業は、過去操作の推測とは区別して残る。今回のテストは従来の統合用構築入力も併用しており、自動捕捉した記録だけで全体を再構築する汎用実行器の完成を示すものではない。

## 自動捕捉の境界

現時点の入口は管理者の投稿・固定ページ・カテゴリー等のREST、CF7の登録REST、通常の記事編集、Markdown取込み、TablePress取込み・保存、WP-Membersの設定・項目操作、会員登録・編集、ACF取込み画面、CF7→Flamingo登録である。入口のコードがあることと、その全経路を実測確認済みであることは区別する。

試験用CLIで直接呼ぶ画像・メニュー・ACF定義APIは、管理HTTP操作の自動捕捉とは別であり、この実験の自動捕捉完了範囲に数えない。媒体のバイナリREST、すべての変更・削除、非管理者、変更のない設定保存、並行操作、製品S3キューへの接続は公開判断の確認済みに含めない。

管理者の認証nonce、会員アカウントのパスワードは再実行素材に含めない。一方、`post_password` は記事の閲覧条件なので、一律のpassword文字列除外で失わせない。原文や構造化値をHTML向けに変換しない。

## 記録開始位置の修正

最初の自動記録ではWP-Membersの項目追加が未確定となった。配布版3.5.8.3では、`includes/class-wp-members.php::load_admin()` がWordPressの `init` から呼ばれ、`wpmem_after_admin_init` で項目保存が行われる。WordPressの `admin_init` で記録を始めると既に遅かった。

入力の捕捉を `init` の先頭へ移し、通常保存より前に記録する。設定の新規追加・更新の両通知を観測する。WP-Membersの初期化関数やinstall.phpを呼ぶ対応はしていない。記録の不備を後からDBの読み取りで成功扱いにする処理も追加していない。

## 小さな境界試験

`tests/construction-operations.php` で以下を確認：

- 通常処理前の入力記録。
- 未確定操作がある場合の追加操作・初回保存の拒否。
- 初回保存の内容を変えず、到達点以降だけを選択。
- 接続情報のない旧初回保存、変更された原本、変更された前半の操作列の拒否。
- 初回保存取得中に操作が進んだ場合の拒否。
- アカウント資格情報と記事の閲覧条件の区別。
- 書込み後にREST応答が失敗した場合を「変更なしの拒否」とせず、未確定のまま保持。

いずれもネットワークなしの専用コンテナで通過。結合結果は別添の機械出力と併せて評価する。

後続の小さな変更として、試験出力の受信状態名を `mail_sent` から `registered_without_sending` に訂正した。実際の送信回数0という測定は上記結合確認で既に得られている。また書込み後のRESTエラーを未確定として残す分岐を追加し、専用単体試験で確認した。

全自動の製品移行を完了したとは報告しない。現在の結合試験は、先に確立した通常構築の実行器も併用している。残るのは、自動捕捉した記録だけで全対応操作の参照を解決する実行器、旧初回保存素材の通常登録結果との接続、未確認の入力経路、正式S3履歴への確定処理である。これらを未完成のまま本番で有効にしない。
