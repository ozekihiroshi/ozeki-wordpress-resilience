## 未達・限界・保証対象外

指定12ケースに未解消の失敗はありません。ただし全ホスティング・全障害タイミングを網羅したものではありません。

**WordPress反映後、正式履歴がS3へ保存される前に元サーバまで失われた場合、その最後の操作は未確定として扱います。** 原本が存在するだけで成功履歴を作りません。確定済みの版までが復旧対象です。ローカルの保留情報は再送用であり、正式な復旧根拠ではありません。

予約状態・予約公開移行時の自動保護、未公開下書きの完全復旧、標準投稿/固定ページの全面対応、任意プラグイン、CSV/Excel、定期Checkpoint、全サイト構築・ネットワーク切替、旧研究全面整理、高度監視はM1対象外です。対象外の通常操作は禁止していません。

全文編集以外のクイック/一括/削除/インポート/API経路、既存文書の一括初期保護、元ユーザーアカウント・投稿者の対応付け、任意URL・埋込み固有構造の復旧も今回の保証外です。復旧した文書の投稿者は通常のWordPress挿入により復旧操作の利用者になります。

ネットワーク公開は管理者の責任です。一律draft化・独自公開承認・外部公開禁止ゲートは製品に入れていません。

## 依存関係と試験の方法

製品はWordPressプラグイン＋S3で、Markdown Documents、PHP、InnoDB、AWS SDKを使用します。AWS SDK 3.392.1は既存依存を再利用し、同梱物とcomposer.lockの一致を確認しました。常設EC2、Pythonワーカー、SSHヘルパー、共有bridge、Dockerは製品の必須依存ではありません。

今回の実S3試験では、既存の実験用分離ロールを使う**試験専用の認証補助**を使用しました。秘密認証情報はホスト外へ搬出していません。この試験補助はZIPに含めず、製品はAWS SDK標準の認証供給を使用します。実際の導入先での標準認証・IAM設定による直接接続は、別途導入確認が必要です。補助経路を本番設定として説明していません。

試験実行環境はWordPress 7.1.3 / PHP 8.3.35 / MariaDB 11.8 / Markdown Documents 0.1.1。最低対応版の全組合せ試験は行っていません。

## 問題の区分

- **プラグイン不具合：** 更新時の文書IDを真偽値化していた問題を修正。ロック後の再取得と、A/Bの安定・別IDの検査を追加。初期候補の結果は最終合格として扱いません。
