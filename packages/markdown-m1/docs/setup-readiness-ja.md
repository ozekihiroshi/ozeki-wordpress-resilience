# 保護開始までの準備状況（0.3.2-dev）

[English](setup-readiness.md) · [導入・復旧ガイド](user-guide-ja.md) · [利用条件](terms-of-use-ja.md)

この画面はGitHubの開発版に追加したものです。WordPress.orgへ申請済みの **0.3.1 rc.2 ZIPには含まれません**。申請済みZIPは変更していません。

WordPress管理画面の利用言語に合わせて、日本語または英語で表示します。定期保存・保持期間・自動整理は「任意」の欄を開いて設定できます。

## 初めて保護を開始する

1. **ツール → Resilience** を開き、上部の「保護開始までの準備状況」を確認します。「対応が必要」の行に、足りない条件と担当者・次の操作が表示されます。
2. 保存先設定の用途を「このサイトを保護」にします。bucket・region・prefix・ownerを[導入ガイド](user-guide-ja.md#2-awsを準備しプラグインを導入する)に従って入力します。保護・定期取得・自動削除はオフのままにします。
3. 利用条件と保存対象を読み、S3への接続の確認欄にチェックして **設定を保存** を押します。確認欄は最初から選択されていません。新規導入では、この設定を保存する前にS3へ接続しません。保存後は既存の履歴表示もS3を読み取ります。
4. **保存先を確認** を押します。接続とバージョン管理を読み取りだけで調べます。データの書き込み・削除、バケット設定の変更はしません。AWS担当者は公開済みの[権限例](aws-setup-ja.md)を使用できます。確認には `s3:GetBucketVersioning` と専用prefixの `s3:ListBucket` が必要です。
5. 環境の不足を解消したら、編集を一時停止し、信頼できる現在のサイトを最初のBaselineとして保存します。**初期保存とサイト全体の復旧 → 現在のサイトが信頼できる状態であることを確認し、編集を一時停止しました。→ 最初の保存を作成** の順に操作します。「最初の保存・読み戻し」が確認済みになります。接続できただけでは、この項目は完了しません。
6. 保存先設定の **保護を開始する** を有効にし、利用条件の確認欄をチェックして保存します。設定変更時も内容を確認するため、この欄は毎回未選択です。その保存先で初期保存を終えていない場合、保護開始を受け付けません。
7. [投稿の保存確認](user-guide-ja.md#4-保護開始を確認する)まで進めます。「保護中」は設定の状態、投稿の保存完了は **投稿などの保存状況** で確認します。

状態は「確認済み」「対応が必要」「未確認」「今回は使用しない」です。保存先を変更すると、その保存先に対応しない結果は使いません。初期保存時と保護開始時にも必要な条件を確認します。利用中の連携の対象は[対応表](../RAADME-jp.md#supported-content-and-plugins)で確認してください。対応する有効な連携は既存の初期保存処理に含まれます。すべての連携を自動診断する画面ではありません。

## 別サイトを復旧する

用途を「別サイトを復旧」にし、保護はオフのまま保存します。保存先を確認したら、**初期保存とサイト全体の復旧** で既存の復旧ポイントを選び、[復旧手順](user-guide-ja.md#6-別のwordpressへ復旧する)へ進みます。復旧先では新しい初期保存を促しません。接続確認にS3への書き込み権限は不要です。

## 既に使用している場合

既存の保存先設定と保護動作は継続します。新しい表示は過去の初期保存を判定し直さないため、「未確認」と表示されても既存データの消失を意味しません。次に設定を保存するときに利用条件を確認してください。保護を無効にしてから再度開始する場合は、この版での初期保存が必要です。保存元が信頼できる状態で行ってください。

確認欄は保存・復旧の内容を理解して開始するためのものです。GPLの権利を制限する追加契約ではありません。確認した利用条件の版・日時・管理者IDをWordPress内に記録します。
