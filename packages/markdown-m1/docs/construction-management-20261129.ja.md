# 保存記録・管理画面・通常登録の接続（2026-11-29）

[English / 詳細](construction-management-20261129.md)

開発ブランチで、次の1〜5に対応する接続実装を追加した。本番への導入、旧復旧画面の置換、公開準備の完了を意味しない。

| 段階 | 今回の実装 | 明示する制約 |
|---|---|---|
| 1．範囲と合格基準 | 保存側の型契約と、復旧時の入口・権限・HTML適用境界を分離。記録が完全でも任意の処理の実行許可にはしない | 全プラグイン・全操作・直接SQLを保証しない。列挙された管理者操作の契約が対象 |
| 2．永続記録 | 入力と成功結果を操作ごとに分離し、入力を書き換えない。欠落・中断・同時書込み・最初の空白理由を保持 | 旧実験記録は自動変換しない。1操作8MiB。全履歴の読込み量は今後の確認事項 |
| 3．管理画面・保全 | 初回保存、通常操作、読み戻し後の履歴確定、日英の状態表示。保護オンの場合だけイベント起点の転送予約 | 定期保存・自動削除は追加していない。失敗を保全成功にしない |
| 4．通常登録 | 管理画面の再構築予約を準備済み実行器へ接続。登録結果の新IDを使用し、同じジョブの二重実行を拒否 | 外部Python／WP-CLI実行器が必要。管理画面だけでは完結しない。結果不明時の自動再開・解決UIは未実装 |
| 5．出荷ガード | 記録不変性、管理接続、入口制限、構造化データの保全、既存審査ガードをActionsへ接続 | 実WordPressでの管理画面試験はdmの専用Dockerで実行。GitHub上の移植可能な統合ジョブには未接続 |

## 記録対象と欠落の扱い

投稿・固定ページ・画像の限定したREST操作、Markdown取込みと編集、TablePress取込み・保存、CF7保存とFlamingo受信、WP-Membersの会員・項目・設定、ACF無料版の取込み・値編集について、既存の保存側契約を使う。

捕捉していない正式データ変更を、投稿・メタデータ・カテゴリー等の関係・会員情報・設定の通知で検知した場合は、入力を後から作らず「未記録の変更あり」とする。単なる再試行・再読込みでこの記録を消さない。ただし、これらの通知を通らない変更まで検出できるとは主張しない。

初回保存前の準備と、保全開始後の空白は区別する。初回保存中の変更は専用マーカーで監視する。未投稿の自動下書きは正式公開の欠落に数えない。正式公開から下書きへ戻す変更は見逃さない。復旧先の準備は保護元の変更ではなく、そのサイトを保存元として使う前に新たな初回保存が必要である。

## 確認結果

- S3なしの軽量試験：入力・結果の不変性、欠落／途中書込み／改変／競合の拒否、保存先変更の拒否、転送失敗時の未確定維持、再試行時の同一確定記録を確認。
- 実WordPressの隔離環境：管理画面の初回保存→ページ作成・追記の自動記録2件→保管先への確定→復旧先管理画面で予約→通常登録→表示・編集→二重実行の拒否を確認。不正nonce拒否と日本語画面も確認した。
- この管理接続の[最終確認](construction-management-20261129-results.json)は40.086秒。S3通信や全対応プラグインを含む本番性能の値ではない。
- 過去の指摘に関係するインストール禁止、準備済み設定、一時領域、移行中断、nonce、無変更時の余計な処理を防ぐ既存試験も通過。
- 新しい適用入口では、任意REST経路や権限移植を拒否し、危険なCF7 HTML／設定は原本を変えず保留。構造化データやMarkdown原文へ一律のHTML変換をかけない。

途中で、実行器の物理的に異なる同一クラスの二重読込みと、WordPressが作る自動下書きのカテゴリー設定を正式データ変更と誤判定する問題を修正した。どちらも復旧先の値や原本を補正して通したものではない。

## 有効化と残る確認

隔離用の2つの明示設定がある場合だけ動作する。既存サイトでは自動起動しない。再構築は管理画面で予約するが、準備済みの外部実行器を管理者が開始する。Webプロセスからシェルを起動しない。認証情報は入力時だけ使い、履歴やコマンド引数へ保存しない。実行証跡はWordPress公開領域外の非公開ディレクトリに置く。

今回の管理接続試験はWordPress標準の代表経路である。全対応プラグインの管理接続を通した往復、実プロセスの並行実行・強制終了、空白の解決手順、安全な表示・再編集の審査事例、大量履歴は、次の検証で確認する必要がある。過去の別入口の成功を新入口の確認済み範囲へ足し合わせない。

したがって「全状況で追随できる」「過去の審査指摘はすべて解消した」「出荷可能」とはまだ判断しない。特に外部実行器の運用条件は、利用者向け公開前に確定する必要がある。
