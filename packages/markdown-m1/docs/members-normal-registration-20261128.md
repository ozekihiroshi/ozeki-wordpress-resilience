# WP-Members：保全素材からの通常登録による再構築

2026-11-28。開発ブランチ上の限定的実装・確認。公開候補の合格判定ではない。

## 目的と原則

これは旧環境を丸ごと戻すバックアップ機能ではない。保全素材を、新しく準備した環境へ通常の登録・設定手順で登録してサイトを構築し直す。

**パスワードは復旧しません。** 新しい会員アカウントを通常登録し、本人がWordPress標準のパスワード再設定を利用する。保存済みハッシュを登録引数に変換したり、DBへ配置したりしない。元の原本に存在するハッシュも変更しない。

復旧先のWordPressとWP-Membersは管理者が事前に導入・セットアップする。再構築処理はプラグインの変更・インストール・初期化を行わない。元の内部IDを維持せず、新しい会員ID・ページIDを用いる。

## 実装

- `MemberReconstruction::plan()` は既存の選択済み素材から会員・項目定義・ページ閲覧条件を選ぶ。登録用計画から `user_pass` を除外する。原本の保存形式・保存処理は変更していない。
- `SiteSnapshot::memberRegistrationPlan()` を開発用入口として追加した。
- `tools/reconstruct-members.py` は隔離環境専用。既存の認証済み管理画面フォームを読み、通常のnonce・入力項目で設定、項目追加、会員追加、プロフィール保存、閲覧条件設定を行う。
- 同じ定義が準備済みなら書き換えない。通常画面から変更できない定義は内部補正で合わせない。
- `--password-reset` ではWordPressの会員追加フォームが用意する新規パスワードを使い、本人による標準の再設定が必要であることを記録する。再設定メールの一括送信機構は追加しない。通常の通知フックは復旧先の設定に従う。
- 対象アカウントが既に存在する場合は流用・上書きしない。途中でプロフィール登録に失敗した場合は作成済みIDを報告し、内部補正や無条件の再作成をしない。

従来の復旧UIをこの処理へ切り替えたものではない。従来経路を含む全体の移行完了を意味しない。

## 確認結果

証拠：`members-normal-registration-20261128-results.json`、`../tests/members-normal-registration/`。

dmの使い捨てDocker、S3なし、WP-Members 3.5.8.3、合成会員1名・項目17件・対象ページ4件で確認した。外部通信を遮断し、メールはMUプラグインで捕捉した。WP-Members本体は未変更。

| 確認 | 結果 |
|---|---|
| 初回素材と通常プロフィール変更後の素材を既存履歴再生へ渡す | 所属の追記を反映 |
| 既存16定義と追加の所属項目 | 既存定義を維持、通常フォームで所属項目を追加。所属定義は保存元と一致 |
| 新しいIDでの登録・ページ参照 | 会員2→3、ページ6〜9→11〜14 |
| パスワードを復旧しない | 旧パスワードではログインできない |
| 標準の再設定 | lostpasswordフォーム→実際に生成されたメールリンク→resetpassフォームで設定成功 |
| WP-Membersの通常ログイン | 新しいパスワードでログイン成功 |
| 会員／非会員の閲覧 | 会員は対象資料を閲覧、非会員には本文非表示、一般ページは閲覧可 |
| 会員プロフィール編集画面 | 正式履歴から選んだ所属値を表示 |
| 準備済み設定 | version/db_version維持。対象ページ参照は新IDへ変更 |
| プラグイン本体・素材 | ファイルハッシュと保存素材ハッシュ不変 |
| 再構築中の初期化 | セットアップ完了後、両環境で `includes/install.php` の読込みなし |

最終試験45.58秒（環境作成・削除込み）。試験環境削除エラーなし。計測は性能保証ではない。

最初の試行ではプラグイン有効化後の通常オンボーディングが未完了で、管理画面自身がinstall.phpを読み込んだ。試験の事前準備として既存の完了フォームを送信し、オプトインは無効にした後、観測を開始して再確認した。再構築に初期化を追加したものではない。

初回の設定保存で `wpmem_settings_logurl` と `wpmem_settings_msurl` の表示値も変化した。これはログイン／プロフィールの新しいページを選択したことに伴う通常処理である。変更項目を生の結果にも残しており、「設定がすべて不変」とは評価しない。

## 確認の限界・保留範囲

- 通常フォームへのHTTP操作と生成HTMLの確認。実ブラウザのJavaScript・視覚操作や実メール配送は未確認。実運用ではメール到達性と会員本人の受信可能性が必要。
- 正式履歴は実際の通常更新後の値を既存形式に凍結し、`MemberHistory::replay()` で再生した合成1件。ライブS3保存・確定キューの試験ではない。
- 承認・確認待ち状態、Hiddenモード2、複数値／ファイル項目、追加製品連携は成立確認していない。内部補正で対応しない。
- 項目順の変更、ダイアログ、利用規約、カスタムURL設定の再構築は今回未対応。旧登録日時など内部状態の一致も目的にしていない。
- 型のコード分岐が存在していても、今回確認した追加定義はtext型の所属項目。選択肢等を確認済みとは扱わない。
- 対象資料は閲覧条件の設定後に試験手順で公開した。ツール自体に自動公開機構を設けていない。
- 今回はログイン・閲覧までの限定確認。全会員構成や再保存・再復旧全体を新方式で確認したとはしていない。

本番・既存の原本と履歴・ZIP・タグは変更していない。GitHubへのpush、公開申請、審査メール返信は行っていない。
