# サイト全体の初期スナップショットと再構築

目的は、本文が読めることだけではなく、新WordPressで元サイトの内容・見た目・ナビゲーション・対応する動作を再現することです。

管理者が信頼した初期状態から、固定ページ・投稿・過去版・テンプレート・メニュー・スタイル、メタデータ、分類、コメント、表示設定、Markdown完全原文、画像・PDF等、利用テーマとMarkdown Documentsのコードを保存します。内容はJSON、原文はそのままのMD、メディアは個別ファイル、コードはファイルごとのハッシュ付きZIPです。DBイメージやSQLダンプをそのまま戻す方式ではありません。認証情報・AWS設定・cronキュー・SMTP秘密情報は移しません。

`site-snapshots/<識別値>/manifest.json` を最後に保存し、すべての資産を固定VersionIdとSHA-256で参照します。Checkpointは全資産を自身の保存範囲へコピーし、後続の正式Markdown・Pages・Posts履歴（新規記事・対応する参照画像・ゴミ箱移動と復帰を含む）を適用します。古いスナップショット資産がなくても復旧できます。欠落履歴・破損資産では停止します。

テーマ・メニュー・テンプレート・分類・任意プラグイン等の後日の変更は、このS3先行保存の履歴へ接続していません。その変更を取り込む際は、新たに信頼を確認した初期状態の採取が必要です。未使用メディア・アイキャッチ変更も継続取得の確認済み範囲外です。Checkpoint時に現行サーバから無断で資産を取り込むことはしません。既存のMarkdown定期実行設定は変更せず、全体の定期実行は後回しです。

信頼済み基準状態の後は、S3の正式履歴に確定した操作までを復旧します。WordPress反映済みでも履歴未確定のまま元サーバを失った場合、その操作は採用しません。新規記事なら含めず、更新なら前の確定版を残します。準備済み原本・ローカルの未確定記録は復旧の採用根拠にしません。最後の未確定操作の救出は完成条件ではありません。元サーバが残っていれば、反映状態を照合して履歴保存を再開できます。

この経路は **Site-wide recovery — primary workflow → Restore complete site** を使用します。補助操作の **Confirmed formal history / Individual recovery** は選んだ本文・属性だけを、同じ資産IDへの更新または新規作成で戻します。画像ファイル・テーマ・メニュー・全体の関連情報は戻さず、無関係な復旧先コンテンツは残します。従来の資産単位スナップショットも補助欄に分け、全体スナップショットと区別します。復旧先の準備は通常の管理者作業であり、常時レプリケーションは必要条件ではありません。投稿状態は再現し、外部公開・DNSは管理者が判断します。

管理画面「ツール → Resilience」に全体初期保存・Checkpoint・復旧先置換を追加しました。現段階の実行依存の選択は利用テーマとMarkdown Documentsです。管理用Backup for S3やPlugin Check、メール接続設定等は除外して記録します。外部ポータル自体やメール配信の移設・実行は今回の成功範囲に含めません。

復旧先には別URL、書込み保護無効、InnoDB、ZipArchive、必要ディレクトリの書込み権限、元と同系列の同じか新しい保守版WordPressが必要です。S3は読取りだけです。全資産を取得・検査してから対象コンテンツを置換し、既存内容・設定・変更対象ファイルをWebルート外へ退避します。コンテンツ内部のIDを維持してメニュー等の参照を再現し、元ユーザーは権限を持たない表示用著者として扱い、管理者の認証は引き継ぎません。

ローカルURLとシリアライズされた参照は復旧先へ置き換えます。Markdown原文は同一バイトで保持し、表示時のリンクを置換します。同じコードファイルはハッシュを確認して再利用します。通常の失敗時は変更済みファイルとDBトランザクションを戻しますが、プロセス強制終了時の自動復帰は未検証です。

## 復旧結果の見方

最後のサイト全体の復旧結果には、成功・失敗・完了未確認、使用したスナップショットのキーとS3 Version ID、Checkpointに含まれる履歴の終端、後続履歴の反映範囲と件数、投稿レコード数・書込みファイル数を表示します。投稿レコード数は公開記事だけでなく全投稿タイプを含み、同一ファイルは再利用されるため書込み0件でもファイルがないとは限りません。失敗・完了未確認の場合、変更0件やロールバック完了とは断定しません。詳細JSONには最新の試行と前回成功結果を残します。この表示は管理用のローカル記録であり、S3正式履歴の代用ではありません。現在の一覧から対象Checkpointを確認できない場合、履歴の境界は推測せず確認不可と表示します。
