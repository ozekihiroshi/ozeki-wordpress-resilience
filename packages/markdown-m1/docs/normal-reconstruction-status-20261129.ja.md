# 保存時の記録と通常登録による再構築：開発状況

[English](normal-reconstruction-status-20261129.md)

後続の[管理画面・保全・実行器接続の実装記録](construction-management-20261129.ja.md)を参照してください。以下は接続前の確認範囲です。

2026-11-28〜29の実装と確認を開発ブランチへまとめたものです。**公開版でも、本番の復旧画面を置き換えた状態でもありません。** 過去の文書は各時点の調査・実験記録であり、すべての成功を現在の保証範囲として足し合わせません。

## 方針

素材と、その素材を通常登録するための入力・参照・成功結果を保存側で記録します。管理者が信頼できるWordPress・テーマ・プラグインを用意し、それぞれの通常の登録・取込み・設定機能を使って再構築します。実行コードの持込み、プラグインのインストール・初期化、旧DBのID強制、登録後の内部状態の補正は行いません。

初回保存は、それ以前に成立している正式な状態を残すために必要です。作者情報と参照契約も保存時に取得します。その後は自動記録した操作を順番どおり追随します。旧IDは参照の識別に使い、新ID・画像URL・CF7ハッシュは通常登録の戻り値から取得します。不足を復旧先で推測せず、結果不明・未対応・不完全な契約は保留します。会員のパスワードは復元せず、通常の再設定を利用します。

現行の統合経路は `ConstructionInitialReferences`、`ConstructionContract` / `ConstructionPluginContract`、`ConstructionEmbeds` / `ConstructionBlocks`、`ConstructionFollow`、`reconstruct-kit.py` です。`ConstructionTransfer` が初回保存と操作記録を確定記録へまとめます。今回の統合試験ではAWSではなくローカルの代替保管を使いました。

初期の `NativeReconstruction` や個別実行器は開発段階の資料として残します。`construction-record.py` と初期試験には試験側が明示した手順があるため、その成功を自動記録の証拠にしません。自動記録の評価には後期の統合・第三サイト試験を使います。本番用の既存復旧エンジンはまだ置き換えていません。

## 互換性と変更の有効範囲

構築記録・アンカーは開発用experiment v5です。初回参照ファイルはschema 2でmediaにcontentsを追加します。schema 1のmediaは読めますが、本文契約の欠落は推測で埋めず保留します。既存保存物は書き換えません。

一方、**通常の保全経路に接続した変更もあります。** `FormHistory` が `ReceiptInputs` を起動し、`CommentHistory` が受信操作ID・確認を扱い、`SiteSnapshot` が入力原本を保存・読み取り、通常登録用の計画取得を公開します。このブランチ全体を「文書だけ」「すべて無効な実験コード」と説明するのは不正確です。本番には未導入です。新しい受信履歴種別・保存形式は、理解できない旧リーダーが不完全に戻さないため区別します。形式と未確定入力の扱いはFlamingoの記録を参照してください。

## 公開前に残ること

1. 対応する操作・項目の範囲と、保留・結果不明の解決手順を確定する。一般利用者向けの解決UIは未完成。
2. 隔離observer／実行器を管理画面と本来の保全処理へ接続する。全UI・API・権限による操作を記録できる状態ではない。
3. 未定義の操作は保存側の契約へ戻す。未知の参照、非管理者編集、並行実行、全体の中断・再開を今回の代表試験だけで保証しない。
4. 保存入力の機密性・保持期間・増加量、最終入口の権限と安全適用、通信失敗時の扱いを吟味する。型の認識だけを無条件の安全保証にしない。準備済み設定の維持と未適用項目の報告を揃える。
5. 統合・範囲確定後、実際に公開するZIPでPlugin Check、導入・更新・最終確認を実施する。今回のソース試験はその代用ではない。

第二段階の結果にある `outage_no_commit: false` は、Aから受け取った既存確定記録も数える試験指標です。そこから「中断時に新しい確定記録が増えなかった」とは判定しません。再確認する際は前後差で測る必要があります。

Actionsは軽量な契約試験と既存回帰・開発ビルドの確認です。dm上のWordPress統合試験やブラウザJavaScriptを再実行するものではありません。ホスト指定の統合スクリプトは、依存ZIPのキャッシュ・専用Docker・補助ファイル配置を必要とし、利用者向けインストーラーではありません。

今回のpushでは、本番・既存原本と履歴・ZIP・タグを変更せず、mainへのマージ・公開・WordPress.org送信・審査メール返信も行いません。
