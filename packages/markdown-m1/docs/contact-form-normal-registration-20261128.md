# Contact Form 7の通常登録による再構築（2026-11-28）

## 方針と実装

CF7自体を変更せず、管理者の通常認証とCF7のREST `/contact-form-7/v1/contact-forms` による新規登録、同 `/{id}` による保存を使う開発用入口を実装した。通常登録が新しいIDと識別文字列を生成し、保存元の数値ID・識別文字列を新しいIDへ対応付けてWordPress標準RESTでページを登録する。

プラグインの内部モデル・初期化関数を復旧処理から呼ばない。内部投稿・メタ・キャッシュ・旧ハッシュを直接配置しない。元の保存素材は変更せず、通常登録で値が失われたり変化した場合は内部補正せず失敗として記録する。

初回保存と正式履歴の読取りには既存のSiteSnapshot::reconstructionMaterialsを使用する。新しいcontactFormRegistrationPlan入口で、保存されたフォーム本文、mail/mail_2、メッセージ、追加設定、locale、表題を通常登録の入力へ組み替える。保存形式は変更していない。正式履歴の削除も選択結果へ反映する。

## 値の一致と通常の既定値

- フォーム原文、独自項目名、メール設定、指定したメッセージ、追加設定、localeを登録後の通常GETで比較する。
- CF7が補う未指定メッセージ、主メールactive=trueは、通常登録の結果として別に記録する。保存済みメッセージを変えてよいという扱いではない。
- CF7標準ひな形はuse_html/exclude_blank等を整数0で保持する。入力はそのまま通常APIへ渡し、CF7自身がbooleanへ正規化する出力を意味の一致として扱い、記録する。Resilienceが内部値を書き換えることはない。
- CF7のconfig_errorsがあれば、新規登録したフォームIDと警告を残すが、ページへの自動埋込みは保留する。警告を削除したり設定を推測で変えたりしない。
- 進行記録のcompletedは処理終了であり、保留ゼロや全機能利用可能を意味しない。

## 隔離試験

専用内部Dockerネットワーク、合成データの保存元と新規復旧先、WordPress 7.1.5 / CF7 6.2.5 / PHP 8.3 / MariaDB 10.11。外部公開ポートなし。S3接続なし。PHPメモリ256MiB、コンテナ各512MiB。定期処理・外部HTTPを無効化した。既存の試験用配布物を読取り・コピーし、使い捨て環境を準備する段階で通常インストールした。再構築処理はインストールしない。

フォームとページは通常APIで作成。初回保存と履歴は既存のシリアライズ/prepare/commit/read/replayを使い、輸送部分をメモリ内オブジェクトへ置換。履歴用合成レコードはFormHistoryの形式に従っている。日常保存フックやS3送信を試験したものではない。

確認対象：初回保存の未編集フォーム、正式履歴で項目が追加されたフォーム、初回保存後の新規フォーム、削除されたフォーム、数値IDと旧ハッシュのページ参照、subscribers_onlyの匿名非表示・認証済み表示。フォーム原文とメッセージを編集し、再保存後も値と表示が維持されること、ページ編集後も埋込みが表示されることを確認する。

表示確認はHTTP応答、登録・編集保存はCF7自身の通常RESTで行う。ブラウザのクリック操作、JavaScriptによる送信・入力検証の網羅、メール配送、Flamingoへの受信登録は今回の確認範囲外。試験フォームは保存元の作成段階からdemo_modeを設定したものと、警告を検証する非demoフォームを使用し、復旧処理で送信設定を変更していない。

## 保留と制限

- 添付ファイル指定、セルではなくフォーム中の画像・外部参照、file等の参照を伴うタグは、復旧先素材との接続が未実装のため保留。
- 未知のフォームタグ、任意の実行命令、未対応の追加設定、HTMLメールは限定入口では保留。通常CF7が技術的に登録できないという判定ではない。
- 既知の追加設定はsubscribers_only/demo_mode/skip_mail/do_not_storeの真偽指定。未知の設定を落として成功扱いにしない。
- HTMLは適用可否を検査し、不適合ならフォームごと保留する。原文を無害化して別物として登録しない。
- SMTP、reCAPTCHAなどの外部サービス設定・認証情報は復旧先の管理者が準備する。今回はこれらを変更しない。
- ページの会員連携、親ページ、複雑なブロック、任意のショートコード属性、文字参照化された埋込みは、限定入口では保留。数値IDとCF7ハッシュが曖昧に衝突する場合も保留する。
- 明示した対応範囲を超えるものを、補正して成立させる実装はない。

## 初回試験での調整

初回試験は表示・編集等が成立したが、CF7の標準フラグ整数0を比較側が拒否していた。また、IPアドレスを使った隔離サイトでは、外国ドメインの送信元だけでは想定した設定警告が出ず、警告の期待条件が不成立だった。初回結果はfirst-pass-result.jsonとして保持した。

数値フラグはCF7の通常入力・出力規則に合わせて比較し、警告用の合成フォームは明らかに不正な宛先に変更して再試験した。既存素材を推測で変更したり、CF7を修正したりしていない。

試験：tests/contact-form-reconstruction.php、tests/contact-form-reconstruction-run.py。

開発用入口であり、既存管理画面の復旧ボタンとの接続や、WordPress/Markdown/TablePressとの一括実行、再保全からの再復旧は今回の範囲外。mainへの取り込み・push・新しいZIPは行っていない。本番・既存の原本と履歴・既存ZIP・タグを変更せず、申請・メール返信も保留。
