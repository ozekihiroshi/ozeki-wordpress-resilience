# WordPress標準の通常登録による再構築：第一段階

2026-11-28。開発ブランチ `codex/native-wordpress-reconstruction`。本番・保存済み原本/履歴・配布ZIP・タグは変更していない。申請・メール返信も行っていない。

## 実装の位置付け

`SiteSnapshot::reconstructionMaterials()` が既存の固定版読取り・正式履歴適用を使って復旧点の素材を確定し、`reconstructNative()` が新しい `NativeReconstruction` に渡す。保存形式・保存処理は変更していない。

今回の実装は第一段階の明示的なCLI入口。隔離環境の指定、管理権限、保存元と異なるURL、保護オフ、現在の完全な更新記録契約を要求する。公開管理画面の復旧ボタンは切り替えていない。全アダプターの置換完了や製品全体の公開準備完了を意味しない。

旧方式は比較と既存導線のために残るが、新入口からの自動フォールバックはない。通常登録が成立しないときに旧DB配置へ戻ることはしない。

## 素材の選択と登録

|対象|今回の扱い|
|---|---|
|初回保存＋指定した正式履歴|既存の連番・固定版・整合性検査を使って選択時点にまとめる。履歴全件を投稿APIへ順番に再送しない|
|投稿・固定ページ|選択時点の公開/非公開の正式な状態を通常登録。初稿下書き、公開停止後の下書き、削除済み、リビジョン一覧は再現しない|
|画像|公開条件が明示された有効な画像を `media_handle_sideload()` で登録。派生画像・メタデータはWordPressに生成させる。旧添付メタを配置しない|
|親子・本文リンク・画像参照・アイキャッチ|新ID対応表から標準の設定API/ブロック入力へ変換。原本は書き換えない|
|カテゴリー・タグ|`wp_insert_term()`、`wp_update_term()`、`wp_set_object_terms()`。準備済みの同名定義との不一致は停止し、上書きで合わせない|
|従来型メニュー|`wp_create_nav_menu()`、`wp_update_nav_menu_item()`。新しい記事/分類IDとメニュー親子を設定|
|ブロックナビゲーション|認識した `wp_navigation` と core/navigation の参照を通常投稿登録で作る。初回保存の素材を確認。日常のブロックナビゲーション変更の追跡を今回新たに保証するものではない|
|表示設定|フロントページ・投稿一覧ページを新IDへ設定。テーマ・テンプレート・任意設定を置換しない|
|著者|管理者が指定した復旧先の既存アカウントへの対応付けを使用。権限や認証情報を取り込まない|
|会員制限等|今回のWordPress標準段階で成立させない。非公開の保留理由を返す。解除して公開しない|

登録は原則として「素材確定→事前判定→画像/投稿枠/定義の通常登録→関係設定→公開状態の設定→通常APIで読戻し」。本文・タイトル・抜粋・親子・公開状態・パスワードの読戻しで相違があれば失敗とし、生成された内部データを修復しない。

準備済み投稿の全削除、`$wpdb->insert` による行配置、キャッシュ/私有メタの再現、プラグインのインストール/初期化は新経路にない。作成したIDと進行状態をオプションへ記録し、既存の実行記録があるサイトで無条件に再実行しない。強制終了からの自動再開は次段階であり、今回の合格条件に含めていない。

## 安全性と未適用の境界

未知の動的ブロック/ショートコード、HTMLの安全検査で意味のある除去が必要になる内容、解決できない参照、会員条件は保留する。画像タグの閉じスラッシュ前の空白正規化は、データ欠落と区別する。構造化された値へ一括HTML変換はかけない。

画像の原本と派生画像の閲覧条件が不明/非公開なら通常の公開メディア領域へ出さない。保留された対象に依存する投稿も公開しない。今回の試験には会員制限付きページを含め、登録されず理由が残ることを確認する。このため、素材全体についての `complete` は false が正しく、対応対象内の成功と区別する。

標準パスワード保護はそのまま通常登録する。ページ制限をファイルの直接URLの制限とみなす処理はない。

## 確認方法

`tests/native-reconstruction.php` と `tests/native-reconstruction-run.py` を使用。dm上に内部ネットワークだけの使い捨てDocker環境を作成し、公開ポートを設けない。MariaDB 10.11、PHP 8.3、WordPress 7.1.5、Twenty Twenty-Five。PHP 256MiB、各コンテナ512MiB。外部HTTPとCronを停止。

ソースは通常のWordPress APIで合成。実装の初回保存形式とStoreのprepare/commitによる正式履歴を作成し、オブジェクトI/Oだけをメモリに差し替える。AWS認証も実S3も不要。WordPressへの登録処理・正式履歴の選択処理は製品のコードを実行する。Resilienceの管理画面や全起動フックを含めたプラグイン有効化試験ではない。

確認対象：

- 初回保存後の本文追記、新規公開、公開停止、削除。途中の履歴番号を選ぶと後の追加/削除が混ざらないこと。
- 下書きや旧リビジョンを登録対象にしないこと。
- 新IDで親子ページ、カテゴリー親子、タグ、アイキャッチ、本文の画像/リンク、メニュー階層が成立すること。
- 原本画像のハッシュ一致。HTTPでの記事・ページ・ホーム・画像表示。
- Cookieログイン＋WordPress標準RESTで記事と固定ページを編集・再保存し、本文と関係が保たれること。
- ブロックナビゲーションのフロント表示と標準RESTでの編集。従来型メニューの標準 `wp_nav_menu()` 出力。
- パスワード保護ページが匿名閲覧で本文を出さないこと。会員制限ページはこの段階では登録しないこと。
- 復旧先の準備済みページと独自設定が残ること。入力オブジェクト群の内容が実行前後で変わらないこと。

HTTP/RESTでの確認であり、ブラウザでのGutenbergクリック操作を実施したとの主張ではない。

## 性能比較の読み方

追加記事10件/100件の2種類の同一素材を、それぞれ旧 `SiteSnapshot::restore()` と新 `reconstructNative()` へ渡す。各3回。対象ごとに新しいDBプレフィックスと独立したアップロード領域を用意する。環境構築・合成素材作成・HTTP編集確認は計測から除外する。計測は素材読取りから適用完了まで。

旧方式は素材に含まれる下書き・リビジョン等の行も扱う。新方式は正式対象を選別し、準備済み情報を残し、通常登録・画像生成・読戻しを行う。同じ入力に対する実際の処理費用の比較であり、両方式の出力や処理内容が完全に同一という意味ではない。

画像は各素材で1点（1200×800 PNG）。画像多数、大容量ファイル、外部プラグインの重い保存フック、実S3待ちを含む全体所要時間は今回の倍率から推定しない。ピークメモリはWP-CLIプロセス全体の値であり、適用処理だけの増分ではない。

最終版で12回（2規模×2方式×3回）の比較が完了。新方式の6回すべてで対象の表示・通常編集・再保存・関係照合に合格。環境構築と撤去も含めた試験全体は95.18秒、撤去エラー0。結果は [JSON記録](native-wordpress-reconstruction-20261128-results.json) に最終ソースのSHA-256とともに残した。

|同一入力の規模（新方式の登録件数）|旧方式の中央値|新方式の中央値|倍率|DBクエリ 旧→新|ピークMiB 旧→新|
|---|---:|---:|---:|---:|---:|
|追加記事10件（計21件）|0.184秒|0.598秒|3.25倍|346→1,039|59.31→55.31|
|追加記事100件（計111件）|0.287秒|1.905秒|6.64倍|886→5,629|61.31→59.31|

登録件数には画像1件、ナビゲーション1件、通常の初期WordPress投稿等も含む。分類・従来型メニューは別。新方式の範囲はそれぞれ0.597～0.615秒、1.869～1.930秒。旧方式は0.179～0.355秒、0.275～0.412秒だった。

新方式の内訳中央値は、画像の通常登録/生成が約0.308/0.311秒、投稿枠登録が約0.062/0.403秒、関係設定が約0.065/0.176秒。残りは本文と公開状態の通常保存、読戻し等。DBクエリ増加を伴うため、旧方式と同等の速さとはいえない。一方、この素材・環境では111件でも約1.9秒であり、再構築方式が実用不能なほど重い結果ではなかった。

実装途中には本文設定と公開状態設定を別々の通常保存で行っていた。これを1回にまとめ、内部の検証やフックを省略せず、111件の中央値を2.378秒→1.905秒、クエリ数を7,017→5,629へ削減した。サイト固有の補正やSQLへの置換は使っていない。

初期試験で分かった事項：HTML検査による画像タグ末尾の空白正規化を、内容除去と誤認していた判定を修正。比較用サイト間でアップロード領域を共有すると旧方式が既存ファイルを検出して停止したため、各比較ケースのアップロード先も分離した。後者を製品コードで回避する変更はしていない。

## 残る範囲

第一段階の選択したWordPress素材についての実装・確認であり、全サイトの自動移行完成ではない。コメント、任意のカスタムフィールド、テーマ固有設定/テンプレート、第三者プラグイン、未知のURL形式やブロック、会員情報、再構築結果からの次の保全・再復旧、強制終了・再開、管理画面への接続は今回の保証に含めない。

通常登録で生成できない状態を、内部メタ配置や再初期化で補う処理は追加しない。この区切りで結果を報告し、次の対象を決める。
