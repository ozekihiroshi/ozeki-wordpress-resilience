# 初回保存・自動記録から通常登録を統合した確認（2026-11-28）

## 結論と適用範囲

代表構成について、初回保存と自動記録だけを入力として、通常登録が返した新IDで投稿・プラグイン間の参照・後続のページ変更を接続できた。投稿者対応表、元サイトの実行中変数、試験用の構築手順を再構築実行器へ渡していない。

ただし全対応操作の統合完了・公開準備完了ではない。今回確認した初回保存後の操作は既存ページのタイトル変更1件である。結果JSONの `reconstruction_completed` はこの合成シナリオの実行完了を示す。実行器の状態名は `registered_pending_remaining_scope_review` のままにしている。

## 実装の接続

- `ConstructionBundle` が保存素材から、正式な投稿・固定ページ・画像、Markdown、表、フォーム、会員設定、ACF、受信登録入力と参照を抽出する。読取り時に保存元へ問い合わせない。
- `reconstruct-kit.py` が実行順とID対応を管理する。投稿者は `ConstructionAuthors::register()` の実際の結果、その他のIDも通常API・管理画面の登録結果から取得する。
- `construction-api.php` は通常のメニュー登録とFlamingo登録のための隔離CLI入口。復旧先管理者はWP-CLIの `--user` で明示し、保存元管理者のIDや権限を流用しない。
- 元にあるページを最初に下書き登録し、そのIDへ画像・ACF・埋込み・閲覧条件を接続する。元にないログインページ等を作らない。
- ACFは対象ページの公開前に通常の取込み・編集で設定する。WP-Membersのページ選択に必要な元のログイン・プロフィールページを公開し、通常の設定画面で新IDを指定する。その後、残りのページを公開する。
- Flamingoには記録済みの通常登録入力を渡す。フォームは再送信しない。
- 初回保存の到達点以降の確定操作を読み、登録済みのページIDへ通常RESTで適用する。未対応の操作を推測して実行しない。

元サイトを作る合成データ手順は試験に必要なため存在するが、実行器はそれを読まない。試験側で保持した元IDは結果の照合にのみ使用する。これは以前の「試験側の手順で復旧先まで作る」確認とは異なる。

## 統合で見つけた実行器側の不備

いずれも今回の開発用統合処理の不備であり、サードパーティを変更して成立させたものではない。

| 不備 | 原因と対応 |
|---|---|
| 標準サンプルページの引用で保留 | 静的な引用内の段落を判定できなかった。安全な静的ブロックを再帰的に判定し、本文は通常登録へそのまま渡す |
| CF7の登録IDが得られない | 統合呼出しに通常保存の `context=save` が欠けていた。既存の通常登録と同じ指定へ修正し、返却IDと保存内容を検証 |
| ACF値設定前にページが公開済み | 会員用ページの公開とACF設定の順序が逆。元のページを下書き登録し、ACFを設定してから公開する |
| ACF値がないページの型エラー | 値集合が空のページにも値保存を要求していた。値がない場合は保存操作不要とする。実フィールドの空文字は保持 |
| ACF取込み後の次の保存がHTTP 500 | 取込みは200で正常終了するがリダイレクトしないため、記録が未確定のまま残った。ACFの公開フック `acf/import_field_group` を捕捉し、入力した全グループの完了が一致した場合だけ確定 |

ACF 6.8.10の正規ソース `includes/post-types/class-acf-field-group.php` では、各フィールド保存とグループ保存の後に取込み完了フックを発行する（確認時559行）。プラグインの保存関数を別途呼んだり、未確定記録を削除したりしていない。

完了通知の全件一致・一部だけ完了した場合の保留は `tests/construction-operations.php` に追加。ネットワークなしのPHP 8.3コンテナで既存の記録契約試験とともに通過。新しいPHPファイルの構文確認と `git diff --check` も通過した。

## 残っている範囲

1. **後続操作の一般化**：現在の実行器が扱う後続操作は既存投稿・ページのタイトル／本文／抜粋のREST更新。新規追加・削除、各プラグインの管理画面変更の再実行は未統合。今回の実証はタイトル更新のみ。
2. **登録全体の中断再開**：保存転送と投稿者・受信登録の限定した再試行は確認済み。全体実行器は不確定な登録を自動再実行せず保留する。全体の中断再開は完成していない。
3. **素材・関係の追加パターン**：階層付きカテゴリー／メニュー、非公開ファイルの配信、複雑なブロック、ハッシュ形式のCF7埋込みなどは今回の実行器で未対応または未確認。推測や内部補正で通していない。
4. **初回保存の全情報**：サイト全体設定・テーマ設定、コメント、独立したナビゲーション投稿、Flamingoアドレス帳単体まで、この実行器で復元できたとはしていない。保存元の原本には残る。編集リビジョンも再構築対象にしていない。
5. **生成される情報**：Flamingo入力に受信日時がない場合、通常登録が日時を生成する。元の保存記録にある日時と同じにする内部補正はしない。今回の受信内容一致はこの日時を除く既存の通常登録契約による。
6. **運用統合**：本製品の通常保存キュー・復旧管理画面との接続、今回の統合経路での再保存後の再復旧は未確認。開発用の隔離入口のまま本番には有効化しない。

本番、既存の原本・履歴、ZIP・タグ、研究側の未コミット変更は変更していない。新しい公開候補作成、GitHubへのpush、WordPress.orgへの申請、メール返信は実施していない。
